# 工作区、维修排程与项目申请调整

## 用户流程

### 从功能目录改为工作区

全站侧栏收拢为工作台、项目、人员与日程、现场资产、消息通知、系统设置、使用反馈；按角色过滤。相关页面在工作区顶部直接显示，旧地址继续有效。

项目内保留五个工作区，每块文字说明包含的功能，当前工作区所有功能按钮直接显示并在手机换行：

- 项目概况：项目首页、周期报告、变更记录、项目设置。
- 开工准备：开工安排、进场准备。
- 计划与人员：项目日程、项目任务、团队。
- 现场处理：问题关注、现场车辆、物品与去向、现场交接。
- 交付资料：交付物、项目文件、验收归档、导出。

设置页不再重复提供成员和任务编辑。自定义任务移至项目任务，成员在团队维护；保留原功能和权限。主导航、细分功能、页面内容各占一层，避免把所有按钮作为同级目录常驻。

### 故障 → 维修 → 个人日程

1. 现场车辆 → 问题履历，记录故障。
2. 点击“安排维修”，选择项目成员、执行日期、预计工时，填写现场要求。
3. “保存并下达”创建同一条项目任务和日程：项目甘特图、人员安排、个人日程共用这条记录，执行人收到通知。
4. 在人员安排点击该项，可以改人、改日期和工作说明。带版本校验，避免覆盖别人刚改的安排。
5. 故障仍由人员维修、试运行验证后手动关闭；排班不等于修复完成。

维修任务以 `Task.source_vehicle_event_id` 关联原始车辆记录。一个问题的重复同人同日提交复用原安排；追加其他日期复用原任务。人工安排锁定并下达，自动排程不会删掉它。普通临时工作也进入“现场追加工作”阶段，无需先配置模板。

草稿、停工和已结束项目不下达新的工作，避免保存后被个人日程的运营项目筛选隐藏；停工项目应先恢复。现场新增工作不自动延长合同周期，也不自动推迟原有安排。

### 人员安排

默认展示人员 × 一周日期。待分配条目可直接点选安排，维修与其他项目工作一并可见。支持切周、按项目/人员筛选、请假不可用提醒、预计超过 8 小时提示。项目筛选后仍显示其他项目的安排数量，避免把已占用人员误判为空闲。

“暂无安排”只代表当前账号可见的项目中没有安排。工时是提示估算，缺失标准工时按每单位 4 小时；不做硬性占用拦截。

### 移交与删除

将笼统的“项目治理”明确为“移交与删除”，与项目列表、实施模板同属项目工作区。项目经理可发起并跟踪自己的申请，总监/管理员处理队列。项目设置也提供同一组件。

- 显示交接说明、原/新负责人、项目当前状态和进度、下一步处理角色、完整意见与处理时间。
- 申请人可撤回未处理申请；驳回需填写原因。
- 删除仍只由管理员最终批准，网页要求输入项目名称确认；底层保留软删除与历史记录。
- 审批时重新校验接收人启用/角色与项目负责人是否变化；请求状态和项目版本用原子更新防并发覆盖。
- 审批结果通知跳回申请记录，避免移交后的原负责人点击通知落入无权访问的旧项目。
- 审批队列一次批量读取项目、用户和进度，不随申请数逐条重复查询。
