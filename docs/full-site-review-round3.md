# 全站功能与排版审查（第三轮）

## 范围

逐项检查 `frontend/src/pages` 的54个非测试页面组件，以及管理端/现场端路由、项目导航与相应后端流程。完整逐页索引见 [覆盖清单](full-site-review-coverage.md)。检查依据为源码、隔离API测试和前端组件测试，不能理解为54个页面都完成了真实浏览器验收。

## 主要修复

### 数据与业务
- 克隆新项目清除旧交付物完成/审核/附件身份，初始化归档要求，保留配置而不带历史完成结果
- JSON快照使用稳定任务标识，支持同名任务恢复；旧格式兼容，歧义明确拒绝
- 车辆关闭一项故障不会覆盖其他未解决故障状态；批量建档部分失败会刷新并明确已建/未确认数量，不自动重放
- 现场交接按提交字段更新，隐藏的既有进场安排不被清空；联系人失败保留草稿
- 甘特整组移动等待全部响应，显示部分成功并刷新；无法刷新时不允许基于旧画面继续拖动
- 归档附件可明确取消关联；耗尽物品补货恢复正确状态
- 人员不可用时间支持查看、修改和取消，保留失败时的输入和记录
- 用户资料编辑重置弹窗上下文，保留正确技能，避免旧密码输入跨用户残留
- 模板Excel导入/导出限定当前模板，其他模板不受影响；空文件不能清空树；导入前确认替换范围
- 模板加载错误可重试，切换模板时旧请求/旧保存回调不能覆盖新模板；准备/采购独立即时保存边界明确
- PostgreSQL备份调用改用受支持的环境复制方法（仅模拟调用验证）；网页提前说明不支持PG恢复

### 页面与操作反馈
- 手机管理端标题恢复可见，账户菜单有明确名称，侧栏有关闭按钮
- 管理/个人日历可键盘操作，使用现有主题色，小屏优先显示日期及数量
- 团队日程/总览加载失败与真正无数据区分，处理过期请求覆盖问题
- 通知先按类型筛选再分页；未读标记后的分页不跳漏
- 历史记录能展开全部已获取条目；反馈筛选回到第一页
- 无权限页面按用户身份返回正确工作入口
- 库存筛选清除与显示一致，全局统计范围明确；工时指标说明估算口径，未擅自重定义人天
- 备份与恢复接入管理员系统设置；非管理员入口与直达路由均受限
- 已撤回/驳回的治理申请不再显示“已批准生效”

## 最终验证

- 后端：完整套件773 passed / 1 skipped / 0 failed；静态压缩项在最终前端产物构建后补跑1 passed，共774项分别验证通过
- 前端：69个测试文件，322项全部通过；测试类型标注修正后的App套件8项再次通过
- 生产构建（TypeScript/Vite/PWA）：通过
- 最终源码快照哈希核对及差异检查：通过
- 依赖既有模拟环境验证，不代表真实PG备份、邮件/消息提供商、外部AI或Docker运行验证通过

## 保留的边界与待决定设计

- 真实浏览器的手机/桌面观感、深色对比、端到端键盘操作尚未验证；本地预览在当前云端浏览器被客户端阻止。需要可访问预览环境或用户截图继续验收
- 未部署到NAS；Docker运行时不可用。Gitea CI需要在线运行器，本地测试不等于服务器CI通过
- PM/worker统一工作入口、按项目能力显示操作的方案已提出，尚未进行整体角色/导航架构改造
- 自动80/90/95阶段推进、验收有效轮次、检查粒度、准备门禁与分批下达规则仍保留原策略
- 工时统计仍按填报样本估算，不代表真实工时或按人员日期去重的人天
- 高级库存字段延续当前刻意简化的录入设计；没有扩成采购/制造执行系统

源码与测试审查能降低已发现问题的风险，不能保证没有未知缺陷。具体检查和限制逐页记在覆盖清单中。
