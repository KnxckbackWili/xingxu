# 全系统成员权限管理（2.3.0，含2.3.1删除政策）

> 本文引用的 QA 回执描述历史时点，原件已[归档](evidence-archive.md)；当前 v3 操作请从[文档入口](index.md)开始。

管理员在“全部功能 → 管理设置 → 成员权限”选择成员后设置权限，也可以直接打开 `/pm/permissions`。本轮覆盖 54 项操作，包含系统功能、个人功能和项目功能。权限修改不改变成员角色；存量成员默认继承原规则。

## 调整方法

1. 搜索姓名、账号或角色，选择需要调整的成员。停用成员也保留在列表中，启用后使用保存的策略。
2. 按模块展开权限。每项提供用途、作用范围、默认角色、当前结果和结果来源；搜索功能名称或说明可快速定位。
3. 选择“继承 / 允许 / 禁止”。继承继续使用角色与项目职责规则；允许授予该项操作；禁止撤销该项操作，包括职责和项目内额外授权原本带来的能力。
4. “本组继承 / 允许 / 禁止”只调整本组当前筛选后显示的可编辑项。高风险项目有提示；管理权限策略的入口保留给真实、启用的系统管理员。
5. 底部固定显示未保存项数。保存成功后策略才生效；取消修改恢复当前已保存值。切换成员或离开页面会提示保存或放弃。

“仅看已调整”查看单独允许或禁止的项。“仅看已允许”查看明确有效的允许项；项目继承项仍按具体项目职责计算，不冒充无条件允许。

另一位管理员同时修改同一成员时，旧页面保存会显示版本冲突并保留输入。读取最新策略后，只把本次明确修改的权限合并到新版本，管理员核对后再次保存，避免覆盖别人调整的其他项。

## 权限如何生效

- 系统权限控制能做什么；项目可见范围控制在哪里做。授予项目修改、日程或物品操作不会让成员看到无关项目。查看普通全局项目是另一项独立权限，仍保留他人个人演示和私有资料的边界。
- 所有策略由后端按当前数据库值检查，撤销后旧登录会话和外部令牌的下一次请求也会被拒绝。前端在重新获得焦点及遇到权限拒绝时同步策略，按钮按当前权限更新，离线填报同步逐项重新校验。
- 工作量目标、执行人限制、已报工/锁定日程、归档只读、进场条件、审核资格和令牌 scope 一起生效。允许一项功能不能绕过这些业务条件。
- 管理车型或账号包含该管理页面必需的读取。模板内容读取独立控制，是模板管理页加载的前提；禁止“使用任务模板”会关闭模板内容GET，即使仍有页面入口或维护权也不能读取。单独“仅查看”适合只读成员；禁止“仅查看”不会撤销另一项明确允许的维护权限，撤销维护应同时把维护项设为禁止。
- 普通业务候选读取继续可用，例如给项目挑选人员、启用车型及人员模板。这不开放管理列表或账号联系方式。组织维护者只能取得维护分组所需的最小成员目录。
- 个人消息、填报记录、文档、AI 对话和受托管理的接口令牌保留本人范围。受托账号维护者不能改变角色、创建管理员、维护管理员账号或为他人发放令牌。
- 登录、认证和本人密码维护保留为基本账号入口；禁止登录通过账号停用办理，停用后旧会话也会失效。
- “管理全系统权限”始终仅属于真实且启用的管理员，不能委派或通过策略关闭。管理员仍可以约束自身的其他业务操作。
- 策略保存记录操作人、目标成员、版本及修改前后值，保存策略与审计在同一事务中完成。

## 常见设置示例

| 需求 | 推荐设置 | 仍保留的限制 |
|---|---|---|
| 现场人员维护任务模板 | 管理任务模板允许；需要导入时再允许导入模板 | 角色保持现场人员，不授予账号或系统配置权限 |
| 只看车型、不修改字典 | 仅查看车型管理页允许，管理车型字典禁止 | 不能新增、启停、改名或排序 |
| 成员只看任务、暂不填报 | 现场填报禁止；提交资料和上报问题分别按需要设置 | 填报与检查不能保存，已获可见权的参考资料仍可查看 |
| 普通人员维护组织 | 管理组织允许，人员账号管理按需要设置 | 最小目录不提供联系方式，不能调整管理员职责或成员角色 |
| 项目协管停止排程 | 管理日程禁止 | 原项目职责或额外授权不会覆盖这项禁止 |
| 允许使用本人外部 AI 令牌 | 管理 AI 接口令牌允许，外部 AI 工具接口允许 | 只能为自己发放；实际业务操作还受相应权限、scope 和项目范围约束 |
| 只查看备份记录 | 查看系统备份允许，创建/下载/删除/恢复分别禁止 | 读取备份记录不等于可取得备份中的全系统数据 |

备份下载、恢复、通知渠道配置、全局项目范围等权限涉及整个系统，应按具体成员职责逐项设置。批量允许之后仍可逐项改回继承或禁止。

项目负责人仍通过项目“人员”里的成员操作授权配置当前项目的额外能力；该操作与全系统策略共同生效。见[项目成员权限说明](project-member-permissions.md)。
