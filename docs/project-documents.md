# 项目资料（T22）

项目资料由 `project_document_definitions`（项目自己的规则快照）、`project_documents`（真实实例）与 `document_versions`（附件版本）组成。模板编辑不回写项目；分组不生成实例，平台不匹配不生成实例，车辆范围绑定真实车辆档案。

新项目复制模板所有叶子要求（公司标准 53 项，3 个组不复制）。旧模板的准备要求和交付要求另外保留为 `stage_key=legacy` 的只读来源，待负责人明确归类。旧阶段 1、2、3 不按序号猜成公司阶段 4、5、6。待分类要求不生成新实例，也不计入公司阶段自动门禁。

## 提交与文件

`GET /projects/{id}/documents` 一次返回实例、规则、未归类文件和当前操作权限。`GET /projects/{id}/documents/files` 可按 `entity_type/entity_id` 读取本项目真实附件，包括已经用于资料版本的文件。

`POST /projects/{id}/documents/files` 接收真实文件和 JSON 数组格式的 `document_ids`。选择多项时，一个附件创建多个资料版本；不选项时进入未归类文件。`POST /documents/submit` 可以再次使用已有的本项目真实附件。提交校验存储路径、文件大小与 SHA256，禁止使用其他项目的附件或资料 ID。版本记录保留提交人、时间、说明和可选审核；被历史版本引用的文件不能删除。退回审核必须有说明，禁止自审；可选审核不改变 `submitted`，不改变门禁。

不适用和撤回提交分别通过 `PUT /documents/{id}`，须有理由；状态不能直接写成 `submitted`。修改操作在同一项目锁和事务中重新读取身份、权限、所属关系并记录审计。上传与后续提交/审计失败时，回滚本次附件元数据与新物理文件，不动原文件。

空白模板通过项目定义的 `blank_file_id` 下载，验证项目权限，不要求来源模板仍存在。它引用独立、不可变的 `document_template_files` 资产，不绑定虚构项目或任务。用户尚未提供公司 4–24 号模板的原件，因此只有模板编号，不造空白附件。

## 修改规则

同一 identity（范围、平台、时机类型、事件、星期、触发类型）内，尚未提交且没有任何版本历史的实例同步名称、编号、模板编号、必需性、说明和默认可见性等字段，并增加实例版本号。已有提交或版本历史保留原始实例快照。改变 identity 用于后续生成，不重写既有历史。`source_metadata` 始终只读，普通创建不能伪造 `legacy`。

显式分类旧资料时，保留原定义和实例 ID、原始来源、所有版本、提交/审核事实。同范围分类复用原实例，不生成重复项。

## 原入口退役与迁移

迁移 `g3a22b000001` 使用冻结 SQL/schema，不导入应用 ORM；精确父链以 Alembic 修订文件为准。重复升级不重复搬迁。

| 原来源 | 新事实 | 保全规则 |
| --- | --- | --- |
| 每个 `Task.deliverables` 元素 | 每项一个规则与实例，默认待分类 | 来源记录保留 task/module/phase/id/index 和原 JSON；原提交人、时间、审核说明、附件均保留 |
| 每条归档清单 | 第 7 或 8 阶段的独立实例 | 保留原分类、要求、完成人、时间和附件，不按同名合并 |
| 每条非采购准备项 | 明确同名的第 4、5 阶段，其他待分类 | 保留整行原字段与关联文件；普通备注不猜成不适用理由 |
| 原附件 | 原项目附件与版本/未归类文件 | 不改原字节，不复制到其他项目；记录实际 SHA256；缺失或大小异常文件不能伪造已提交 |

原 `done/passed` 没有真实可用附件时保留旧完成声明到来源元数据，当前实例保持待补。旧 `Task.deliverables` 清空，不再生成或编辑。归档清单 HTTP 与旧提交资料、附件上传/列表、准备事项 CRUD、模板准备项 HTTP 已删除。采购保留为 `/projects/{id}/procurements`，是 4.4 的明细入口；`extra` 按键合并，数量/规格/单位改变撤销原完成确认，未知旧字段保留。

原非采购准备行和归档表只保留为冻结历史。发车前确认使用[当前资料确认](pre-dispatch-documents.md)，旧准备评审汇总不作为新确认来源。启动 seed 不再回填任务交付物或旧准备事项。

验收范围指纹对迁移任务从只读来源重建原 v1 定义，不因搬家令原有效验收失效，也不把原已失效验收变有效。新第 4–7 阶段实例参与范围；第 8、9 阶段在归档检查，不提前阻塞 completed。完成门禁和人工状态规则见[完成核对](completion-review.md)与[项目状态](project-lifecycle-v3.md)。

## 复制、导入导出与保全

项目 clone 复制规则，实际提交重新等待真实附件，保留空白模板资产归属。新项目 JSON 导入是计划导入：源实例与版本作为 `portable_unverified_snapshot` 只读来源，不能凭源附件 ID 取得新项目文件或提交资格。旧 JSON 的交付、归档、非采购准备要求转为待分类定义，旧模板 JSON 交付要求也转为带来源的 legacy 定义，普通树 PUT 仍拒绝写回旧字段。

JSON 便携导出包含规则、空白模板实际二进制、实例和历史版本元数据。项目 Excel 以“项目资料 / 资料版本历史 / 资料要求快照 / 采购明细”显示新事实，文本按字面量导出。项目 ZIP 包含真实项目附件和 SHA256 manifest。完整恢复使用加密系统备份；计划 JSON 不声称恢复原始证据。

删除备份与保留期清理快照包含新规则、实例、版本、空白模板元数据及实际二进制 manifest。正常删除恢复原项目及原 ID；旧项目物理清理先保留完整资料事实，再按 FK 安全顺序清理版本引用。原字节仍由不可变保留快照拥有。

Agent `documents_read` 需要 `projects:read` 和 `files:read`，遵守同样项目/保密边界；`template_get` 返回 `document_requirements`。内部 AI 通过 `get_project_documents` 读取同一聚合。

## 当前关联规则

- [截止与周次](document-deadlines.md)按真实事件、项目时区和规则生效时间生成；改期仅更新未提交资料，不伪造历史周期义务。
- [事故、质量与离场](triggered-documents.md)使用真实源引用和时间；`lifetime` 仅在真实内部启动会后建档。
- [生成表单](generated-document-forms.md)从当前获准真实记录生成 Excel/Word，并原子保存实际附件与新版本。
- [保密](confidential-documents.md)同时核对文件独立范围和全部资料家族；管理员、项目角色或上传者身份不提供隐式放行。[外部查看](external-view.md)始终拒绝保密资料。
- 项目回收站没有到期自动物理清除；[永久删除](project-retention.md)先核对完整加密备份，旧周[策略清理](resumable-storage.md)保留精确凭据，不把普通缺失冒充已授权清除。

迁移测试分别构造 SQLite、PostgreSQL 的 g3a21 数据，升级并重复升级后核对旧 7 个项目资料来源、4 个版本、原字段/审核事实、附件数量和文件 SHA256，执行 schema/metadata 对账。真实旧备份全链迁移由 T60 独立执行，不在业务卷上试验。
