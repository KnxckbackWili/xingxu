# 项目资料

项目资料由 `project_document_definitions`（项目自己的规则快照）、`project_documents`（真实实例）与 `document_versions`（附件版本）组成。模板编辑不回写项目；分组不生成实例，平台不匹配不生成实例，车辆范围绑定真实车辆档案。

新项目复制模板所有叶子要求（公司标准 53 项，3 个组不复制）。每项要求都归入第 4–9 阶段。

## 提交与文件

`GET /projects/{id}/documents` 一次返回实例、规则、未归类文件和当前操作权限。`GET /projects/{id}/documents/files` 可按 `entity_type/entity_id` 读取本项目真实附件，包括已经用于资料版本的文件。

`POST /projects/{id}/documents/files` 接收真实文件和 JSON 数组格式的 `document_ids`。选择多项时，一个附件创建多个资料版本；不选项时进入未归类文件。`POST /documents/submit` 可以再次使用已有的本项目真实附件。提交校验存储路径、文件大小与 SHA256，禁止使用其他项目的附件或资料 ID。版本记录保留提交人、时间、说明和可选审核；被历史版本引用的文件不能删除。退回审核必须有说明，禁止自审；可选审核不改变 `submitted`，不改变门禁。

不适用和撤回提交分别通过 `PUT /documents/{id}`，须有理由；状态不能直接写成 `submitted`。修改操作在同一项目锁和事务中重新读取身份、权限、所属关系并记录审计。上传与后续提交/审计失败时，回滚本次附件元数据与新物理文件，不动原文件。

空白模板通过项目定义的 `blank_file_id` 下载，验证项目权限，不要求来源模板仍存在。它引用独立、不可变的 `document_template_files` 资产，不绑定虚构项目或任务。用户尚未提供公司 4–24 号模板的原件，因此只有模板编号，不造空白附件。

## 修改规则

同一 identity（范围、平台、时机类型、事件、星期、触发类型）内，尚未提交且没有任何版本历史的实例同步名称、编号、模板编号、必需性、说明和默认可见性等字段，并增加实例版本号。已有提交或版本历史保留原始实例快照。改变 identity 用于后续生成，不重写既有历史。`source_metadata` 始终只读。

显式分类待分类资料时，保留原定义和实例 ID、原始来源、所有版本与提交事实。同范围分类复用原实例，不生成重复项。

## 与项目状态的关系

资料是否齐全不影响项目状态推进，状态由人工确认，见[项目状态](project-lifecycle-v3.md)。采购明细在 `/projects/{id}/procurements`。

## 复制、导入导出与保全

项目 clone 复制规则，实际提交重新等待真实附件，保留空白模板资产归属。JSON 导入只复制资料要求和空白模板；源项目的提交和附件不带入新项目，需要时用完整加密备份恢复。导入只认当前导出格式。

JSON 便携导出包含规则、空白模板实际二进制、实例和历史版本元数据。项目 Excel 以“项目资料 / 资料版本历史 / 资料要求快照 / 采购明细”显示新事实，文本按字面量导出。项目 ZIP 包含真实项目附件和 SHA256 manifest。完整恢复使用加密系统备份；计划 JSON 不声称恢复原始证据。

删除备份与保留期清理快照包含新规则、实例、版本、空白模板元数据及实际二进制 manifest。正常删除恢复原项目及原 ID；旧项目物理清理先保留完整资料事实，再按 FK 安全顺序清理版本引用。原字节仍由不可变保留快照拥有。

## 当前关联规则

- [截止与周次](document-deadlines.md)按真实事件、项目时区和规则生效时间生成；改期仅更新未提交资料，不伪造历史周期义务。
- [事故、质量与离场](triggered-documents.md)使用真实源引用和时间；`lifetime` 仅在真实内部启动会后建档。
- [生成表单](generated-document-forms.md)从当前获准真实记录生成 Excel/Word，并原子保存实际附件与新版本。
- [保密](confidential-documents.md)同时核对文件独立范围和全部资料家族；系统管理员或上传者身份不提供隐式放行。
- 项目回收站没有到期自动物理清除；[永久删除](project-retention.md)先核对完整加密备份，旧周[策略清理](resumable-storage.md)保留精确凭据，不把普通缺失冒充已授权清除。
