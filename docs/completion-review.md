# 完成前核对与资料交付

概况中的“完成前核对”和“归档前核对”读取当前项目证据，一次列出未满足条件及对应入口。该查询不写项目、不自动推进状态；真正提交状态时仍会重新检查，不能把早先的核对结果当成批准。

必需资料使用项目自己的资料实例和真实原件，第4–7阶段参与完成检查，第8–9阶段另在归档检查。不适用须有理由，可选审核不改变已提交状态。原始待分类要求保留来源，分类后才参与明确的公司阶段规则。安全检查不能通过“直接完成”覆盖；不通过的普通检查项仅在明确填写理由后可覆盖，并记录当时检查项ID、版本和失败原因。以后检查项出现新版本或新失败，不沿用旧批准。重新打开清除当前完成资格，审计中的原理由及快照继续保留；旧直接完成记录不会被迁移推定为已批准覆盖。

问题仅关闭或作废算闭环，已解决仍待确认。被指派处理人可以填写处理进展和解决说明，关闭/作废由项目经理、原报告人或管理员操作，作废必须填写理由。仍未关闭的车辆故障独立列为阻塞项。

验收记录保留最新有效结论和范围校验。选择本项目可读取的真实验收附件时，同时提交已有的7.1项目验收单实例；同一附件不会重复增加相同的当前资料版本。没有7.1的旧项目不会凭空增加新义务，无附件的验收记录不能替代必需资料附件。

资料页可勾选有真实提交的资料并下载所选最新版本。压缩包只包含所选资料的最新原件和清单，同一个文件被多项引用时只收一份；清单写明资料ID、版本ID、附件ID及实际字节哈希。整批校验项目归属、资料和文件可读性及原件大小/哈希，任何一项缺失或无权限都拒绝整包，不静默漏项。源文件分块读取，压缩结果超过8MiB后转临时磁盘，响应结束释放临时文件。只读账号保留其被授权的导出能力，不能借此上传或新增要求。

默认交付Excel的六张表及完整JSON/项目包的保全边界见[项目交付工作簿](project-delivery-workbook.md)。
