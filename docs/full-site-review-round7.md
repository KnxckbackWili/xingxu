# 第七轮：落实三项确认的流程规则

基线：第六轮远端提交 `29842617b01d24280e3e62188ddef96e6611035b`。本轮仅落实已确认的三项生命周期规则及其必要的一致性、兼容和恢复修复。

## 已改变的实际操作

1. **未满足条件，先确认风险进场。** 缺少必需/阻塞准备项或清单为空时，需要对当前准备快照明确选择风险进场并写理由。旧警告参数、直接调用状态接口、回退或停工恢复都不能绕过。普通可选且不阻塞的事项保留提醒。
2. **结项和归档核对最新有效验收。** 按项目当地已生效的验收日期确定最新记录，同日按录入顺序判断。后来拒绝、有条件通过或范围不符时，不能跳过去拿旧通过记录结项。补录较早日期只补历史；新验收日期不得晚于项目当地今天。
3. **联调、试运行、验收由人确认。** 有对应项目权限的人通过相邻状态操作推进或退回。报工、数量修正、撤回、任务完成及重复计算不再因 80/90/95% 阈值改变这些阶段；计划下达关联的计划中/待进场行为保留。

总览、准备、开工、验收归档和交接页面统一展示上述规则及失败后的处理路径。后端给出同一份验收判定，页面不再自行寻找任意历史通过记录。

## 旧项目与导入注意事项

- 新增可空验收范围字段，保留历史签字，不伪造过去的范围记录。旧的已完成/已归档状态不因读取而改变。
- 历史签字缺少可验证范围、或验收后任务/必需质量与交付范围改变时，新的结项/归档决定需复核并重新录入验收。人员、项目备注、填报数量和普通展示顺序不会使范围失效。
- 归档恢复可先回已完成，再回验收中纠错；再次归档仍需满足当前门禁。
- 新项目 JSON 导入只接受草稿、准备中、计划中、待进场。后期状态在预检及执行时明确拒绝，不静默重置；完整系统备份恢复是另一条流程。
- 修复旧启动迁移将合法 planning/archived 改写为其他状态的问题，重复启动保持当前合法阶段与归档只读。已被旧实现改成未知状态的真实记录不自动猜测修复，需依据原备份或审计核对。
- 提交交付证据保留要求说明；缺失、NULL、空文字及等价值数字规范化，避免正常保存误触发范围变更。
