| 项目阶段 | 正常下一步与依据 |
|---|---|
| 草稿 | 保存资料和实施方案；负责人明确开始项目准备 |
| 准备中 | 落实现场条件、任务目标与人员；进入计划中安排日程 |
| 计划中 | 核对执行人、日期、数量并下达；日程下达关联待进场状态 |
| 待进场 | 核对当前准备清单和实际开工；未满足条件须有效风险进场评审与理由 |
| 现场实施 | 记录数量、质量和交付，由授权人确认系统联调 |
| 系统联调 | 核对联调情况和问题，由授权人确认试运行 |
| 试运行 | 核对运行情况和遗留问题，由授权人确认进入验收中 |
| 验收中 | 任务数量/质量、必需交付、问题闭环及当前范围最新有效验收均满足后确认完成 |
| 已完成 | 必需归档资料与复盘齐备，重新核对当前完成和验收依据后归档 |
| 已归档 | 只读查看；整改须授权恢复已完成，再回验收中，历史保留 |
| 突发停工 | 记录原因，只能恢复停工前阶段；恢复实施再次核对进场条件 |

准备清单的“已就绪”是独立评审结果；任务阶段是工作分组；数量百分比不会自动推进联调、试运行或验收。相邻顺序、风险进场、当前验收范围、完成与归档门禁、权限均沿用现有契约。

## 操作路径与验证范围

1. `/pm/projects?create=1`：任选方案、填资料/车辆、确认创建；概况显示草稿，刷新仍草稿，无下达安排。
2. 概况“开始项目准备”→准备中；填写任务目标和执行人员→计划中；预排/下达→待进场。草稿可以预排，下达需先开始准备；本轮实际草稿预排33条/已下达0，下达和临时安排按钮均禁用并提供概况入口。
3. 待进场条件未满足，推进实施被拒并明确当前原因；一键到准备评审，按实际清单完成或明确批准风险并写理由，再由授权人确认实施。
4. 实施→联调→试运行→验收均逐级明确确认；取消不请求。填报/百分比不会代替这些人工决定。
5. 验收不满足数量/检查/交付/问题/当前验收时，完成拒绝并提供处理入口；补齐后完成/归档，保留原门禁与复盘要求。
6. 无状态JSON导入与网页克隆均为草稿；显式历史初始状态预检规则保留，实施及后续状态不静默导入。未获状态管理权限的普通成员不能切换阶段；已有明确授权策略保留。

本轮已实际完成上述创建、草稿预排与禁止下达、准备至现场实施以及下方数量快捷编辑路径，具体步骤见[14项网页结果](usability-remediation-2026-10-06.md)。后续阶段、导入克隆和更多权限排列的契约测试与历史网页证据分别保留，不称为本轮重新穷举；没有操作NAS正式数据。
