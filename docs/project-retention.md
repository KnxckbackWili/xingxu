# 项目回收站与永久删除（#85）

项目删除统一进入回收站，原项目 ID、状态、成员、业务记录和文件继续保留，回收站项目不会因时间到期自动物理删除。原 `purge_soft_deleted` 定时任务已移除，兼容函数只返回停用结果；旧 `SOFT_DELETE_RETENTION_DAYS` 设置不再生效。权限仍按项目可见范围、删除权限和显式拒绝检查。

正常删除前保留项目备份。新备份为 T12 的 AES-256-GCM/scrypt 加密信封，ZIP 内容流式写入密文文件，文件模式 0600，目录 0700；大文件不整包读入内存。管理员须先配置 T12 备份口令，缺口令、文件丢失或备份失败时项目不会删除。回收站还原会复用原项目和数据，从经校验的备份补回缺失文件；已有不同内容的文件不会被覆盖。

旧明文 ZIP 不改写、不自动删除；网页按需加密后下载，临时目录随响应清理，不原样下发明文。新加密备份可在口令轮换后继续按完整密文哈希下载；离线解密时需要创建该备份时的口令。回收站从加密包补文件时使用当前配置的口令，若曾轮换，管理员应先核对原口令并恢复相应配置后再还原。

## 管理员明确永久删除

仅系统管理员可执行，权限键为 `system.projects.purge`；显式禁止项目读取、删除、导出或永久删除都会阻止操作。普通成员即使获其他项目权限也不能永久删除。

1. 在回收站选择「永久删除」，生成并校验当前项目的加密备份。
2. 下载备份，安全保管，并勾选已保存。
3. 输入完整项目名称，再确认永久删除。

准备凭据绑定项目 ID、删除周期、项目版本、全部项目记录、操作者资料及文件哈希。正式删除再次鉴权并核对证据和密文；任何记录、文件、版本、删除周期或加密备份变化都拒绝删除，须重新核对并生成备份。项目及全部受影响的 FK 子记录持有数据库锁，按 FK 依赖顺序删除子记录，再删除项目，兼容资料版本对原附件的 RESTRICT 约束。快照未涵盖的旧记录、未知新表或跨项目异常关联会阻止删除。关联个人日程不会混入项目备份，由其所有者改挂后方可继续。

永久删除后不能从回收站还原。独立备份凭据和加密文件继续保留，管理员可在回收站「永久删除备份」中再次下载。下载仍要登录、权限有效且哈希匹配；接口不接受用户传入文件路径，不返回备份口令。审计写入与数据库删除同一事务；备份或审计失败都会保留项目。原上传文件不在本事务中直接清扫，文件维护须继续核对所有引用及已验证备份。

需要离线查看备份时，受信宿主操作员可使用现有 T12 工具；口令只从私有文件读取，不能出现在命令行参数、日志或工单：

```bash
python docker/scripts/backup_runtime.py decrypt-file \
  --data-dir /private/recovery \
  --input /private/project.zip.agvenc \
  --output /private/recovery/project.zip \
  --passphrase-file /private/original-backup-password
```

输出须是尚不存在的文件，权限为 0600；在私有目录检查 ZIP 内 `project-backup.json` 与 `files/`。这是完整证据备份，不自动导入成新项目、不补造执行或验收资格。完整系统恢复仍使用 T12 协议。

## 旧数据与兼容接口

增量 `g3a85b000001` 创建不随项目级联删除的 `project_permanent_backups`。已有无当前回收凭据的软删除项目按原删除时间补入回收站，不改业务行、不在启动时生成备份或要求口令。旧项目没有备份时，只要原记录和引用文件完整即可还原；缺文件会拒绝，不能假装证据完整。

本 v3 版本继续保留升级前的 `project_archives`、只读查询及文件引用保护，接口增加 `legacy_read_only` 提示，不创建新的归档快照，不自动删除旧归档。移除旧归档属于后续版本的数据交接工作。本轮迁移不会清空或去重旧快照。

接口：`POST /api/project-recycle-bin/projects/{id}/permanent-backup` 准备，`DELETE .../projects/{id}/permanent` 明确删除，`GET .../permanent-backups` 列表，`GET .../backups/{backup_id}` 鉴权下载。准备需要版本和删除周期；删除还需备份凭据 ID 和完整名称。全系统备份同时保全该表、旧 ZIP 与新 `.zip.agvenc`，恢复不丢失永久备份下载凭据。

## 验证与容量

项目备份计数字段在 PostgreSQL 使用 BIGINT、SQLite 使用其原生 64 位 INTEGER，迁移保留旧值并验证 5 GiB 数值往返。ZIP64 与流式加密支持大包，相关删除、恢复、准备及下载请求使用较长等待窗口，不因默认 15 秒请求超时轻易放弃备份。

本轮 Python 3.12、PostgreSQL 17 隔离验证覆盖：普通删除/还原/多次删除周期、原文件恢复冲突、旧明文仅加密下载、永久备份在项目级联删除后仍可鉴权获取、版本/周期/历史快照/文件及密文篡改拒绝、审计失败回滚、并发永久删除仅一方成功、迟到 FK 插入不能提交未备份证据、未知归属后代拒绝删除。旧归档只读权限、文件哈希、个人日程所有权及 SQLite FK 恢复保护继续验证。新旧库结构含服务端默认值核对无差异，SQLite/PostgreSQL 离线 SQL 均已生成。
