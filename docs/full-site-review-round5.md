# 第五轮全功能与流程复查

本轮基于独立仓库提交 `07faf7e54c`，按真实业务链、异常中断和跨账号/跨项目边界复核。前端 55 个页面组件逐项覆盖见 [第五轮前端清单](full-site-review-round5-frontend.md)；生命周期和现场执行细节分别见 [生命周期报告](project-lifecycle-round5-review.md) 与 [现场执行报告](field-execution-round5-review.md)。

## 主要修复

### 从建项到归档
- AI 排程建议只匹配本项目有效人员及唯一任务；拒绝同名歧义，不修改已有下达、填报和结束历史
- 已完成项目的排程调整统一要求先恢复；归档、撤权和重排删除草稿后的过期操作明确拒绝
- 自动排程保留已结束/取消记录，取消的未执行数量不再占用剩余目标或推迟新安排
- 准备影响关联、验收与归档证据附件验证项目归属；准备评审核对日期变化和现场时区
- 项目移交复用既有人员交接检查，未交接的已下达工作不会因负责人被移除而失联

### 现场执行与多端协作
- 合成 SQLite 双会话复现并修复报工超量与重复领料；项目优先事务锁后重新校验当前权限及状态
- 数量上限和撤回/修正使用原始累计值，避免显示用小数舍入造成超量或负数
- 离线请求保留 UUID 和版本，成功凭证优先确认；旧账号返回的请求不会写进新账号队列/缓存
- 交付物续交保留原要求、参考元数据及未改动的审核身份；换附件须重新提交，同名歧义与跨项目附件拒绝
- 检查项通过/不通过/不适用状态一致，车辆问题重开恢复异常提示
- 前端补充过期请求防护、版本透传、同步提交锁与失败保留/重试反馈

### 模板、账号及系统工具
- 停用再启用账号不会让旧登录会话重新有效
- 用户资料与技能同一事务保存；组织成员批量调整部分失败会刷新并要求核对
- 模板 JSON 可跨模板导入；Excel 往返保留匹配节点身份及不在表格中的描述、交付要求、参考资料等信息，导入与审计同事务
- 恢复包校验 SQLite 完整性、应用结构及规范路径；并发上传隔离，准备恢复失败不破坏先前有效包
- 恢复替换失败回滚旧数据库、附件、密钥及相关文件；同秒备份使用唯一名称且完成后原子发布
- Cookie 登录的 AI 桥接正确携带身份；测试均使用模拟提供商
- 文档收集箱不会根据同名项目自动选错归档目标；令牌、车型字典和备份界面补充重复操作、账号切换和加载失败保护

## 覆盖与验证

逐模块源码审查、隔离 API 与前端组件回归、真实 SQLite 双会话并发及受控故障注入分别记录。认证边界扫描覆盖 255 个 HTTP 操作，其中 250 个非公开操作在无凭据时均返回 401；这不等于每一种角色权限组合都已穷举。

部署脚本通过 shell 语法检查，备份校验/轮转的独立函数级回归 7 项通过。构建产物通过服务器深链接、静态资源和 PWA 文件传输检查；这些都不能代替真实浏览器视觉验收或 Docker 运行验证。

最终全量结果：

- 后端：924 passed，0 failed，0 skipped（生产锁定依赖，Python 3.12，隔离 SQLite）
- 前端：77 个文件，405 passed，0 failed，0 skipped（2 个 worker，单项超时预算 15 秒）
- TypeScript 与 Vite/PWA 生产构建通过
- 既有测试的业务日期改为明确的项目时区日期；备份路由测试等待同一预期异步 GET 后再断言，没有放宽业务断言
- 初次并行运行遇既有测试 5 秒超时，原样单文件重跑通过；最终完整运行使用上述较低并发设置

## 保留的业务决策与验证限制

- 自动 80/90/95% 阶段推进、历史验收通过记录是否仍有效、检查按任务还是逐车/逐批、正常/风险进场门禁和分批下达政策保持原策略
- 单件任务需三天施工时，现有计划数量可能为 1/0/0；是否拆成小数或单独显示工期占用，需要先确定业务口径
- 库存/车辆旧编辑表单没有全域强制版本字段；本轮不声称排除了所有长时间打开的表单覆盖
- 模板 Excel 按同层级名称匹配，新增/改名视为新节点，歧义拒绝；JSON/Excel 不是跨实例二进制附件备份
- 未运行真实 PostgreSQL 并发、真实 NAS 断电恢复、外部 AI/通知服务或 Docker 容器
- 真实手机/桌面页面视觉验收仍需要可访问运行环境；服务器 CI 需要在线运行器

没有测试能够保证不存在未知缺陷。这里明确区分已复现修复、已验证路径和仍未验证的范围。
