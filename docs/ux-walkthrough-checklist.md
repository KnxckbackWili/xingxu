# 页面/流程走查清单（UX 整改）

> 面向「内容多、分散注意力、一上来不知道关注什么、流程太复杂」的产品反馈，
> 对全部页面与主流程逐一走查，记录走查结论与整改动作。
> 配套 PR #3（`docs/optimization-report.md` 为整改思路，本文件为逐页核验清单）。
> 覆盖范围：**全部 7 个权限角色 × 全部页面 × 全部主流程**，逐条记录步骤、负担点与整改判断。

## 走查范围

- 角色：7 个权限角色全覆盖——
  - 系统管理员 `admin` / 总监 `director` / 技术经理 `lead` / 项目经理 `pm` / 技术工程师 `technician` / 实施工程师 `worker` / 实习工程师 `intern`
  - 路由边界（App.tsx）：`/pm` 允许 admin/director/lead/pm/technician/worker；`/worker` 允许 worker/intern/technician/pm/lead/admin（**intern 仅现场端**）
  - 页面级守卫：dashboard/people/stats 限 admin/director/lead/pm/technician；templates/users 限 admin；governance 限 admin/director
- 入口：登录 → 角色落地页 → 各页面主流程 → 全局组件
- 判定标准：首屏认知负担、信息噪音（重复展示）、操作步数与复杂度、移动端触控（≥44px）、UI 一致性

## 五、主流程走查（步骤 → 负担点 → 整改判断）

| 流程 | 实际步骤 | 负担点 | 整改判断 |
|---|---|---|---|
| 登录 → 角色落地 → 浏览 | 账号密码登录 `/login` → 后端按角色返回 → 前端按 `PM_WORKBENCH_ROLES` 落地（admin/director/lead/pm/technician → `/pm/dashboard`，worker/intern → `/worker/today`）→ 侧栏/底部导航进入各页 | 落地后首屏是否直接可用是关键，不能让用户再找入口 | ✅ 落地页即核心工作台，首屏 5 秒可判断；intern 落地已修正为 `/worker`（曾导向无权限 `/pm` → 403） |
| 新建项目（选模板→表单→模块→生成任务） | `/pm/projects`「新建项目」→ 5 步向导：①选模板 → ②项目信息（名称/客户/地点/时间/负责人/计划进场）→ ③勾选实施模块与条件项（新造车/WMS/自动充电/客户服务器/海外）→ ④确认 → ⑤自动生成任务并进项目 | 模板选择直接决定任务与准备项生成；条件项开关过多会淹没首步 | ✅ 向导分步把每一步压成单一决策；条件项默认只勾「新造车」，其余按需，无需整改 |
| 排程生成 → 预览确认 → 下达 vN | 项目日程 → 设「排程规则」（休息模式/节假日/手动休息日）→「生成排程」→ 预览 Modal（新增/移除/日期变动/锁定保留说明）→ 确认 → 记为 vN 并通知成员 | 无确认直接生成会覆盖已有排程；锁定条目若被动则破坏现场安排 | ✅ 预览 Modal 防误操作 + 版本号可追溯 + 锁定保留说明，已达要求 |
| 现场填报（离线队列→自动/手动同步） | 今日任务 `/worker/today` → 任务数量 +/−/完成 → 检查项打勾（安全项红标）→ 交付物勾选+拍照上传 → 断网入离线队列 → 联网自动同步（可手动） | 断网填报若无提示会以为已提交；退出前未同步记录可能丢 | ✅ 离线状态提示 + 恢复自动同步 + 退出前未同步 Modal 警告（已有），无需整改 |
| 问题上报 → 指派 → 处理 → 解决 → 关闭 | 今日任务/项目问题页上报（分类 → 分类专属字段 → 严重度 → 附件）→ 通知负责人/处理人 → 处理人接手（未指派时谁开始处理谁是处理人）→ 解决 → 关闭，全程时间线留痕 | 分类专属字段缺失会误导台账；处理人模糊导致无人接单 | ✅ 全流程闭环 + 分类专属字段 + 指派变更通知，无需整改 |
| 交付物提交 → 审核（通过/退回） | 执行计划任务 Drawer 交付物区：成员勾选完成+上传附件 → 提交待审 → PM「通过/退回」→ 退回必填原因 → 成员可见原因重新提交 | 退回无原因时现场不知改什么 | ✅ 退回原因必填（已有），无需整改 |
| 导出（Excel 13 Sheet / JSON 备份 / 甘特 PDF） | 项目头部「更多」→ 导出 → 三选一：Excel（13 Sheet 全量）/ JSON 备份（可导入恢复）/ 甘特 PDF（新窗口打印） | 选项多但用途清晰；大文件等待时长 | ✅ 一键导出 + 用途说明，无需整改 |
| 准备就绪 → 确认进场 | 准备页/执行计划「项目准备」阶段 → 就绪状态四态（准备中/有风险/待确认/已就绪）→ 评审流生成清单（已满足/未满足/风险项）→ 三选一（暂不进场/有风险进场[必填原因]/确认具备）→ 结论+快照留痕 → 通知 PM | 就绪判断条件多（必需项/逾期/阻塞/预计晚于要求），需一眼看懂卡在哪 | ✅ 评审流三选一 + 快照留痕，状态带直接给出卡点，无需整改 |
| 消息处理（通知铃 → 详情 → 前往处理） | 顶栏铃铛未读数字 → 下拉最近 20 条 → 点击跳转相关页面 → 已读/全部已读；消息通知 `/pm/messages`、`/worker/messages` 分页 + 类型筛选 | 通知跳转若落不到具体对象会打断操作 | ✅ 跳转相关页面 + 已读管理，无需整改 |
