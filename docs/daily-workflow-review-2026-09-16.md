# 日常项目使用流程审视

## 使用问题与调整

### 看得到问题，但到不了处理位置

- 团队页增加「下一步：分配日程」，连接安排成员与下达工作。
- 交付列表和总览的待交付项可直接打开对应任务的交付文件页；已完成任务也能通过此入口打开，不受待办筛选影响。
- 现场项目详情只展示分配给本人的今日任务，点击任务直接展开相应填报卡。
- 归档清单可进入项目文件查找或上传；文件支持名称搜索、分页和移动端横向滚动，关联附件支持完整名称搜索。

### 上传成功不等于审核通过

交付列表原来根据 done 显示已交付，不能区分等待审核与审核通过。现在显示待提交、待审核、已通过、已退回；默认待处理列表保留待审核和退回项，并展示退回原因。下载使用响应头里的实际文件名，保留扩展名。

### 网络问题不能伪装成没有工作

- 修复归档加载失败后读取空进度造成的白屏；支持重试。
- 项目计划、项目日程、个人日程、文件与交付列表明确区分加载失败和没有记录。
- 现场项目详情显示部分数据不可用，进度请求失败不再假定为0%。
- 个人日程列表修正周日的周起始日计算，避免跳到下周遗漏当周安排。
- 总览随项目状态变更重新加载，避免沿用切换前的数据。

### 上报失败后的结果必须明确

今日任务内的问题上报使用稳定请求标识防重复；问题保存后保留其ID，附件失败时只补传尚未成功的附件，不再新建问题。此时提示已保存的范围并锁定问题正文，避免使用者误以为再次提交会修改已保存的正文。

- 审视项目启动、成员安排、排程、现场填报、问题、交付、文件、归档，并对车辆、物品、周期报告及导出入口做代码检查。
- 浏览器实际验证：交付列表 → 对应任务交付页，归档 → 项目文件，团队 → 日程；390px手机归档布局。
- 开发实例9个主要项目读取接口返回200。

- 前端47个文件、242项测试全部通过；新增回归覆盖直达任务、审核状态、错误重试、问题重试幂等及附件补传；生产构建通过。

这些检查不表示所有页面或所有异常组合已被穷尽。此次以能减少实际使用中断点的明确问题为修改范围，保留现有权限及业务数据。
