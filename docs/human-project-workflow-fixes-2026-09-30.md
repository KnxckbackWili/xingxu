# 项目协调流程修复（2026-09-30，第二轮）

## 范围

本轮从项目经理实际办理流程出发，修复人员交接、准备需求变更及日期维护的明确断点。采购与生产仍限于项目协调，不扩展为采购执行或制造执行系统。本文不是上线或部署证明。

## 已交付行为

### 人员调离先交接

移除项目成员时，如其仍有未完成的已下达工作，整次成员更新会被拒绝。页面保留选择，列出执行人、任务及日期，并提供项目日程改派入口。先加入接替人、在日程中改派或取消相关安排，再移除原成员。

已完成数量、手动完成及日程结束状态会被识别；数量完成但必需或安全检查仍待处理时，不能留下无人承接的质量事项。接替人须为当前项目的在职成员，并已有同一任务的已下达、未结束安排。普通检查沿用既有人工完成规则，安全检查不因人工完成而跳过。已取消日程不阻止移除；已完成项目的历史成员调整不被视为当前现场工作。归档只读限制保持不变。

不自动搬移部分填报，不修改原报工人员或完成记录。已有未下达安排仍按原规则转为待分配。

### 准备需求变化重新核对

准备事项的数量、规格或单位发生实际变化时，原通过或不适用状态重开为待确认，当前完成日期和完成人信息清空；项目进场确认失效，并显示重新核对原因。同次表单带回旧“已通过”状态也不能沿用旧确认。

旧需求、完成日期与完成信息保留在变更审计中，旧评审记录保持不变。新评审快照包含数量、规格等专属信息，已打开的旧评审页面不能确认变化后的需求。备注和联系人等非实质调整不触发上述重开规则。

采购到货状态继续独立于准备通过状态。已到货但尚未确认准备完成的事项仍显示在待处理清单，并标注“已到货，待准备确认”。本轮未将到货自动等同于验收或可用。

### 明确内部跟进人

准备清单展示并允许指定、清除已有内部跟进人字段。新增指派须选择启用的系统用户；跨部门协调人员不必因此加入现场执行团队。内部跟进人负责协调责任方和落实下一步，不代替采购或生产的实际执行人，也不自动授予项目权限。

### 可以维护计划进场日期

项目设置增加计划进场日期编辑和清除。日期变化保存前，展示已有要求日期的未完成准备事项，并提供准备清单及现有日程链接供核对。较长清单显示前八项和其余数量。

本次仅保存进场日期；不自动平移准备要求日期、供应商承诺日期、实际完成日期或已有日程。PM按真实情况分别调整，避免把历史事实或外部承诺当作可机械平移的日期。

## 保持原有的业务政策

- 未改变正常进场与有风险进场的必需/可选事项门禁政策
- 未改变全项目日程下达范围或引入新的分批发布制度
- 未新增制造工单、工序、采购审批、库存执行或财务结算
- 未自动改派工作、重写历史填报或替用户接受进场风险

## 定向验证

本轮PM相关后端测试两个文件共23项通过，随后新增“质量交接必须有当前成员的同任务已下达接替安排”测试单独通过，共24项分次验证。前端准备、团队和项目设置三个测试文件共6项通过；差异空白检查通过。

这些结果仅代表定向回归，不替代第二轮最终快照的完整测试、生产构建或浏览器端到端验证。全量验证由独立验证流程另行记录。
