# 现场本周、人员周视图和实际记录

现场默认入口是“本周”：读取已发布给本人的周计划、真实车辆环节和检查、本周可见待交资料、本人未闭环问题。待认领格子单独展示，只有明确点击“认领”才分配给本人；查看或登记不会静默认领。协助登记必须明确选择启用的项目成员；关联周计划时还须匹配其负责人名单。实际操作人由服务器会话确定。

“人员”按人员 × 周展示可见项目安排、不可用时段和同周多项目提示。团队范围要求工作台权限，本人范围独立要求个人周计划读取权限；有本人权限不代表有团队权限。不可用原因、备注继续沿原人员隐私规则过滤。跨项目日期线导致当地当前周不同时，统一周一日期展示并说明差异。

“我的记录”按完成日期所在周查看实际操作与修订历史。完成日期是项目当地日期；登记时间保存服务器 UTC 时间，两者分别展示。默认补记范围为项目当地本周及上周，未来日期拒绝；宿主可通过 `FIELD_BACKFILL_DAYS=1…90` 改为包含今天的滚动天数，留空使用默认两周规则。

## 实际操作与修订

- `POST /api/worker/operations` 登记 work、vehicle 或 check。请求包含 project_id、目标身份、版本、完成日期、理由、原 client_uuid，以及可选的 weekly_cell_id、明确的 assisted_user_id。客户端不能指定实际 actor。
- `GET /api/worker/records` 返回本人当前可见项目中的记录及服务器判断的修改/撤回资格。
- `PUT /api/worker/records/{id}` 修订本人当前记录的日期和附注；`DELETE` 撤回本人当前记录，均须版本、原操作编号和理由。
- `GET /api/worker/week-report` 是本人按周实际事实；项目周/月报告通过 `/api/projects/{id}/report` 读取同一套事实、资料提交和已发布下期周计划。

所有写入先锁项目，再按统一账号锚点锁定实际人员并刷新账号、会话版本和权限，重新检查项目归属、生命周期、对象及版本。车辆完成复用真实矩阵及逐车检查；非车辆完成复用工作项服务；检查沿原必需、安全和不适用规则。备注或日期修订不会产生新的完成资格，不会刷新已经确认的普通失败检查覆盖版本。

实际记录追加保存，不覆盖原行。逻辑原记录、修订、撤回与恢复来源分别记录；撤回一次日期/备注修订会恢复上一个实际事实，个人与项目报告同步重新计入它。撤回原记录则取消该逻辑记录的有效性。后续操作已经改变目标时，旧记录不能覆盖当前事实。登记时间保持真实原值，单调操作序号保证系统时间相同或回退时仍能识别最新修订。

重新打开当前工作状态是受原工作项资格约束的新观察记录，保留原完成事实；它不是修改他人的原始记录。对原记录 ID 的修改/撤回仍只允许本人。所有状态、操作凭据及 `log_change()` 在同一事务提交，审计失败一起回滚。

## 离线与共享账号

新勾选使用 `field` 操作类型进入原账号隔离队列；原 UUID 与完整 payload 在重试时保持不变，同编号换内容会拒绝。资料文件沿断点上传和原期次 ID 核验，问题沿原幂等上报。离线队列表示“待同步”，不会被显示为服务器已经完成。

旧数量 HTTP 入口认证后返回 410。旧队列仅当 UUID、原日期、数量、备注和来源精确对应原历史行时确认已保存；不能对应的操作继续留在 deferred 队列，不转成新完成事实，不再写 DailyProgress。

浏览器视图先核验其捕获账号；请求显式携带 `X-AGV-Expected-Account`。同步请求拦截器在请求调用时捕获账号，不能在异步派发或刷新重试时改标为另一账号；服务器在该可选 header 与实际认证账号不符时拒绝。原 CLI/Bearer 调用不带该 header 的契约保留。

新周视图和实际备注不写 HTTP API 缓存。Service Worker 不缓存 API 导航或响应，激活时清除旧 API 快照及旧页面缓存中的 API 原件；操作队列和上传 IndexedDB 单独保留。已打开的本周视图可继续离线排队，重开且不能读取时明确显示未知。

## 保密与保全

待交资料、模板和下载沿当前资料/文件家族 ACL；有授权的保密元数据读取审计。实际备注、操作记录和普通 JSON 中出现的受限资料名称/文件名按同一 ACL 脱敏。项目页只读展示进度、当前资料和授权空白模板，实际登记回到本周。

FieldOperation 完整列入项目保全快照，实际 actor 与 assisted 的两份人员来源分别保留。永久删除前的严格关联扫描能在密文快照中逐主键证明这些行，备份认证失败时不删除项目。系统/项目私有加密备份保留原文；普通便携 JSON 的 `field_operation_evidence` 标为只读、未核验来源，导入只保存到 portable source，不创建实际记录或继承完成、检查、账号身份资格。

按日安排、日数量/工时工作量、容量指标、旧人员安排和旧“今天”接口已经退役。它们的旧行保持只读来源；当前统计保留 `/api/dashboard/statistics` 的独立 `insights.view` 权限。旧个人事项仍只供原所有者维护与保全，不参与新业务计划、完成或工作量计算。

T33 直接消费 T40 的已发布格、统一序列化与完成事实；认领、取消、改派和批次/车型范围使用同一份当前计划，不复制计划模型。逐车检查与车辆勾选都核对计划范围。读取失败时页面显示读取错误，不回退旧排程或用零项冒充已读。

补记窗口也适用于原车辆进度写入口，管理员和负责人同样不能通过该入口登记窗口外或未来的完成日期。迁移按 g34 → g40 → g33 单链执行，原周格、发布和人员来源完整保留，绝不从计划负责人推断实际操作人。
