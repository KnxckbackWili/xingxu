# 以办理工作为中心的项目流程重整

## 使用障碍

1. 新建项目直接落到完整任务表，却没有把工作量、成员、日程和进场确认连成办理过程。
2. 目标数量逐条打开弹窗；成员又在单独弹窗；日程默认月历，只露出每天两条。简单确认需要许多点击。
3. 17 个项目入口占据页面顶部，部分内容再重复一层页内标签；显示更多菜单并没有减少理解成本。
4. 模板是工作起点，却归在系统设置；创建时的现场条件还藏在「更多信息」中。

## 本轮方向

- 项目日常入口与开工办理分工明确。新建后进入「开工安排」：确认工作 → 安排人员 → 排定日程 → 核对进场，显示每步真实配置情况，步骤可直接切换。
- 工作量在清单中填写并一起保存；后端以一个事务校验权限和版本，任一冲突均不部分保存。
- 成员在页面中直接安排。排程默认显示清单，日期、任务、执行人和下达状态在一起；保留日历与甘特图。
- 桌面项目功能固定在左侧，所有入口展开，不再占用顶部；手机采用紧凑、完整的文字目录。去掉现场、交付、动态页面重复导航。
- 模板归入项目工作；创建过程明确模板只是起点，现场条件直接显示，创建成功后连续办理。
- 维持项目数据、原 URL、权限与生命周期校验，实际开工仍需明确确认。

## 已落实与验证

- 开工安排的四步均直接可见，并可通过 URL 回到具体步骤。新项目默认准备中，创建成功直接进入开工安排；存量项目保留原状态。
- 工作量批量保存包含任务版本号；项目隔离、权限检查、已下达与执行阶段保护继续有效。失败保留本次输入，冲突可明确放弃修改并刷新。
- 手机任务表改为任务卡片，检查、参考、交付三个入口直接在卡片中显示。
- 去除现场信息、交付、动态页面与项目目录重复的标签栏；原深链仍可直接访问。
- 演示项目实际完成 7 项缺失数量填写（分两批）、增加参与人员、生成 38 条排程；清单直接显示日期、执行人和下达状态。
- 后端 45 项任务、权限、排程、总览及新增批量保存回归通过，包含末项冲突时前项数据和版本整体回滚。
- 前端 51 个文件、256 项回归通过；最终构建、窄屏与部署记录将在发布验证后补充。
- 创建向导取消「先勾一次工作、填完资料再确认一遍」的重复步骤：选方案只看阶段概要，最后确认工作一次。
- 浏览器从选模板、填写项目及车辆、确认方案走完创建；自动落在新项目 `/start`，初始为准备中，正确显示待填数量与待安排人员。
- 320/390/768px 检查步骤与页面无横向溢出；手机当前工作自动定位，顶部明确提供目录定位链接，完整 18 项入口可见。
- 最终生产构建通过；完整前端 256 项通过，后续针对创建、步骤、工作量与项目壳的定向回归通过。
- 发布前用 SQLite backup API 备份 7001 数据库（权限 0600，quick_check=ok）；本轮新增接口但无数据库迁移。继续绑定 `0.0.0.0:7001`，由原 NPM 域名访问。
