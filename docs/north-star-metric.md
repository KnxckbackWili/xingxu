# 北极星指标试点方案（已确认日程按计划执行率 OTE）

> 适用版本：v2.1.0+（审视 v3 P2-指标）
> 更新日期：2026-08-25
> 状态：**试点方案**（非生产放行门槛）。上线后随 `GET /api/north-star` 跑基线对照，试点期结束评审是否转正为北极星看板指标。

## 一、为什么选它做北极星

AGV 项目管理系统以「项目建档 → 任务生成 → 排程确认 → 现场填报 → 交付验收」为主链路。其中**排程确认 → 现场按排程填报** 是唯一每天真实发生的执行环节：日程是否被现场按计划执行，直接反映项目交付节奏与排程质量。

北极星候选定为：**已确认日程按计划执行率（On-Time Execution Rate，OTE）**。

- 由真实业务数据驱动：只统计「已确认」日程与「现场填报」，无填报即不计入分子，杜绝空转项目虚高。
- 与排程/填报双端联动：PM 确认排程、现场按时填报，指标即上升；谁拖期都能在口径下反映。
- 可分层拆解：按项目、按阶段、按人下钻（试点期先出全局口径，二期再做下钻）。

## 二、口径（Definition）

| 项 | 定义 |
|---|---|
| 指标名 | `on_time_execution_rate`（已确认日程按计划执行率） |
| 观察窗口 | 默认滚动 **14 天**（可传 `days` 1–90） |
| 基线窗口 | 观察窗口之前的 **28 天**（可传 `baseline_days` 1–180） |
| 分母 | 窗口内 **已确认**（`is_confirmed = true`）且 **计划日 ≤ 观察日** 的日程条目数 |
| 分子 | 分母条目中「按计划执行」的条目数 |
| 按计划执行判定 | ① 存在填报（`daily_progress` 有该条目记录）且 **最早填报日期 ≤ 计划日**；② 有量纲任务（`planned_quantity > 0`）时 **累计完成量 ≥ 计划量**；③ 无量纲任务（计划量为 0）只要有填报即算 |
| 未按期情形 | 无填报；首次填报晚于计划日；或累计完成量未达到计划量 |
| 基线对照 | 当期 OTE − 基线 OTE = `delta`；无历史数据时基线 `rate = null`，`delta = null`，试点首期只记录当期值 |

**边界规则**

- 只统计**已确认**日程：草稿/未确认排程不参与，防止 PM 反复重排造成分母波动。
- 只统计**已到期**条目（`work_date ≤ as_of`）：未来条目不提前计入分母。
- 跨项目合并统计（全局口径），不区分项目规模，避免试点期样本过小。

## 三、统计实现

- 服务：`backend/app/services/north_star.py` —— `compute_north_star(db, days, baseline_days, as_of)`
- 端点：`GET /api/north-star?days=14&baseline_days=28`（登录即可读，与其余洞察一致；只返回聚合统计，不暴露个人/明细）
- 数据来源：`schedule_entries`（已确认+计划日+计划量）+ `daily_progress`（按 `schedule_entry_id` 聚合累计完成量、最早填报日期）
- 返回示例：

```json
{
  "metric": "on_time_execution_rate",
  "name": "已确认日程按计划执行率",
  "as_of": "2026-09-15",
  "window_days": 14,
  "window": {"start": "2026-09-02", "end": "2026-09-15"},
  "current": {"total": 6, "on_time": 3, "rate": 0.5},
  "baseline": {"total": 3, "on_time": 1, "rate": 0.3333, "window_days": 28, "start": "2026-08-05", "end": "2026-09-01"},
  "delta": 0.1667
}
```

## 四、试点方案

1. **试点范围**：全局（全部活跃项目合并）。8002 验收环境用演示数据跑通口径与展示，生产上线后再以真实数据累积基线。
2. **试点周期**：上线后 **8 周**。首期只记录当期 OTE 作为起点基线；此后每 **双周** 取当期窗口 OTE，与启动基线对照（`delta`）。
3. **成功标准**：试点结束当期 OTE ≥ 基线 + 5pp 且 ≥ 85%；若基线为 null（无历史数据），以首期 OTE 为基线重新计时。
4. **数据卫生要求**：试点依赖「已确认排程 + 现场按时填报」。需在项目治理中约定：PM 必须确认排程后再进入执行；现场需按日填报，未按期填报即视为未按期执行。
5. **人工输入项**：北极星口径不含外部真实数据；演示环境使用演示账号与演示项目，真实客户数据与基线需在生产环境由运营人工确认后录入。
