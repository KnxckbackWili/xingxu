# 项目状态与签单里程碑

项目状态为准备（preparing）、现场实施（executing）、验收中（acceptance）、已完成（completed）、已归档（archived），另保留突发停工（suspended）。原“筹备”和“待进场”已合并为“准备”（见下文“阶段合并”）。新项目、克隆和便携方案导入从准备开始。填报、数量调整、资料上传、任务重新打开、发布或撤回日程均不自动修改项目状态；状态只能由有权限的人明确推进，并再次核对当前证据。

准备进入现场实施时一次核对原两道门禁：第4阶段必需资料有真实文件或明确的不适用理由，且第5阶段发车前资料齐备或已有仍然有效的风险批准；缺项一次列出。现场实施进入验收中需到货签收单、调试完工单、上线运行单、培训记录表，缺项一次列出；不适用同样必须说明理由。完成和归档继续经过对应门禁。状态只能逐级推进或回退一级（准备 ⇄ 现场实施 ⇄ 验收中 ⇄ 已完成 ⇄ 已归档）。突发停工必须有理由，只能明确恢复停工前合法状态，恢复时仍重新检查门禁。验收记录在进入现场实施后才能录入。

概况中的每次人工状态切换（推进、回退）都先弹出确认框，写明从哪个状态变为哪个状态，可填写可选说明；说明随状态审计一起保存，归档另需复盘、停工另需理由。状态审计以结构化字段记录原状态和新状态（`{"status": ...}`），资料截止服务据此读取现场实施的真实开始时间。

新建项目只需名称、实施周期和模板（默认带入模板全部工作）；客户、地点、车型、人员等在项目中补全。概况在准备阶段顺序展示基本资料（客户、地点）、车型、人员、资料清单、周计划、发车前资料确认，标题为“进入「现场实施」还差 N 项”。原开工向导书签转入概况，保留已配置内容。工作完成百分比和下一阶段提示只是证据和导航，不是状态决定。

联调和试运行作为“调试完工”“上线运行”关键事件保存。上传对应签单时可填写签单记载的真实业务日期；未填日期只保存文件，不采用上传时间。仅精确到日的日期写入actual_date，actual_at保持空，不把午夜伪装成实际发生时刻。用户也可以明确登记日期或带时区的实际时间。签单日期与已登记时间矛盾时拒绝整批提交，请负责人核对后明确更正；源资料版本和事件来源保留，实际事件变更参加项目版本校验。

旧draft/planning转准备（当时称筹备），commissioning/pilot转现场实施，其余合法状态一一对应；停工前状态同步映射。legacy_lifecycle保留原状态和停工上下文，更新时不改原更新时间。只有真实人工状态推进审计能提供里程碑补登时间；来源明确标注为原推进审计时间，不声称是签单业务时间。缺审计时不凭旧状态猜测时刻，已有实际事件不被覆盖。

无法识别的旧状态统一为待核对的停工状态，原值保留，禁止业务修改。管理员查阅备份和审计后填写依据，明确重置为准备，再按实际资料逐阶段推进；此操作不自动授予验收或完成资格。数据库约束防止重新写入已退役或未知状态。

迁移需要真实审计记录，在Alembic在线事务中执行；离线SQL明确拒绝代替数据迁移。失败需整笔回滚；降级通过升级前一致加密备份恢复，不能直接丢弃来源列。

## 阶段合并（g3a90b000001）

原“待进场”（ready）并入“准备”。在线迁移把状态为待进场的项目改为准备，把停工前状态为待进场的停工项目的停工前状态改为准备；每个项目的原值写入 `legacy_lifecycle.ready_merge`（原状态、原停工前状态、迁移号），版本加一并写一条项目操作记录，另有一条迁移汇总记录。数据库状态约束随后不再接受 ready。旧 JSON 导入中的 ready 视同筹备类状态，统一落为准备。降级需恢复升级前一致加密备份。
