# 项目状态与签单日期

项目状态为准备（preparing）、现场实施（executing）、验收中（acceptance）、已完成（completed）、已归档（archived），另有突发停工（suspended）。新项目、克隆和便携方案导入从准备开始。

状态只是“项目现在走到哪一步”的人工记录，由有状态权限的人按实际情况推进，系统不核对资料、进度、问题或验收结论。填报、数量调整、资料上传、任务重开都不会自动改状态。

- 状态逐级推进或退回一级：准备 ⇄ 现场实施 ⇄ 验收中 ⇄ 已完成 ⇄ 已归档。
- 每次切换都先弹出确认框，写明从哪个状态变为哪个状态，可填写可选说明；说明随状态审计一起保存。状态审计以结构化字段记录原状态和新状态（`{"status": ...}`），资料截止服务据此读取现场实施的真实开始时间。
- 归档时填写项目复盘（成功经验、问题教训、改进建议），没有复盘不能归档。
- 突发停工必须填写原因，只能从准备、现场实施、验收中进入；恢复时回到停工前的状态。
- 验收记录在进入现场实施后才能录入。

概况顶部是一条状态栏：当前状态、一句话说明下一步做什么、“推进到「下一状态」”按钮，以及“调整项目状态”菜单（退回上一状态、突发停工）。下面“现在要处理”列出未关闭问题、逾期资料、周计划和本周待交资料，只是入口，不是推进条件。新建项目只需名称、实施周期和模板；客户、地点、车型、人员等在项目中补全。

联调和试运行作为“调试完工”“上线运行”关键事件保存。上传对应签单时可填写签单记载的真实业务日期；未填日期只保存文件，不采用上传时间。仅精确到日的日期写入actual_date，actual_at保持空，不把午夜伪装成实际发生时刻。用户也可以明确登记日期或带时区的实际时间。签单日期与已登记时间矛盾时拒绝整批提交，请负责人核对后明确更正；源资料版本和事件来源保留，实际事件变更参加项目版本校验。


数据库约束只允许上述状态值。
