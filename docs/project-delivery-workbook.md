# 项目交付 Excel（T27）

项目 Excel 默认提供六张工作表，面向交付核对；完整任务计划、日程、填报、采购、交接及授权附件仍可通过 JSON 或完整项目包取得。专用生命周期表、质量反馈单的原导入导出接口保持原用途和版式。

| 工作表 | 格式与内容 |
| --- | --- |
| 交付概览 | 项目基本信息、执行进度、未闭环问题、可见资料与文件数量、计划/实际关键事件，以及车辆环节定义、真实逐车单元格、历史未知车号完成凭证和只读导入来源。 |
| 生命周期表 | 第2行前11列与 `report_forms.LIFECYCLE_HEADERS` 一致；追加故障部位、原因、完整配件、停机时间、验证、关闭状态、事件后状态/位置、操作者、可见附件、扩展字段及单车档案。没有问题记录的车辆仍保留建档行。 |
| 问题清单 | 采用质量反馈单的项目、类型、反馈人、车型、车辆编号、来源、部件、提交日期和现象术语；保留问题状态代码、闭环标志、处理说明及完整扩展字段。仅 closed / cancelled 算闭环，resolved 保留为已解决。 |
| 物资清单 | 第1行前10列与资料项9.2生成表一致；保留分类、管理方式、状态、供应方、到场/归还日期、最低库存和扩展字段。 |
| 收发流水 | 第1行前10列与9.2生成表一致；全部不可变流水按时间和ID输出，补充物品/流水ID、操作者和时间依据原值。旧记录没有可靠时区时明确标注原记录，不能伪装成UTC。 |
| 交付资料 | 合并资料清单、可见文件版本和未归类文件，保留周次、截止时间、状态、提交者、文件哈希及版本审核信息。 |

通用表有标题行、表头、冻结窗格、筛选和打印重复表头；物资两表保留9.2的首行表头。长字段按“记录分段”续行，不在 Excel 32767 字符处静默截断，分段按原顺序拼回即为完整字段；续行仅重复记录标识，数量不重复。控制字符以可见 Unicode 转义呈现；所有用户/来源文本以字符串存储，不作为公式执行。

导出要求明确当前账号，并重查项目可见性及导出权限。资料使用 `can_read_document`、文件使用 `can_read_file`；隐藏资料引用的文件不会从未归类区域或完整包文件清单绕出。工作簿和完整包共享这一文件范围。系统一致加密备份、#85项目加密备份继续走各自的私有快照入口，不依赖 Excel 或默认账号。

JSON 新增 `execution_evidence` 只读来源块，包含完整车辆矩阵/历史凭证，并记录当前任务直接完成状态、原理由、精确检查覆盖快照，以及检查项当前状态/版本/失败原因、原操作时间与操作者展示名。便携导入忽略这些执行资格，重新导入后仍是新项目：不继承直接完成、通过检查或验收资格，原数量报告也不作为新项目活跃报工；日期、操作者、数量、备注、UUID 完整保存在只读来源。原事实保存在源 JSON/完整包中；便携导入还将完整原字段保存为 `portable_unverified_snapshot`，可在车辆页查阅，不应用为本项目完成资格。系统一致加密备份和存量前向迁移继续保全真实执行事实。

专用测试实际生成并重新打开 XLSX，核对六表契约、原表头前缀、75条流水、全部故障/问题字段、长文本续行、公式及控制字符安全、双层保密过滤、完整包清单和只读执行事实的重导边界；SQLite 与 PostgreSQL 使用独立测试数据库。
