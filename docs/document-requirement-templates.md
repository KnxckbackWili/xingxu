# 资料要求模板（T21）

模板中心的“资料要求”按第 4–9 阶段配置资料名称、编号、范围、平台、输出时机和默认保密属性。系统预置任务书全部 56 行：53 项资料、3 个分组。第 1–3 阶段没有资料种子。

## 编辑和空白文件

在模板库打开模板，切到“资料”页签：“新增资料要求”添加，点一行编辑，删除在该行的 ⋯ 菜单。每台车一份的要求选择“每台车”；平台留空表示全部平台适用。

“每周”必须选择星期。事件前/后和里程碑规则必须选择事件及非负小时；事件触发规则必须选择事故、质量问题或人员离开。全周期资料在内部启动会建档，归档前提交。仅车辆范围能选择“该车到场”。分组只提供目录，不生成待提交资料。

空白文件在资料行的 ⋯ 菜单里上传、替换、下载或移除引用，单文件不超过 10MB。任务书只给出了模板编号，没有提供实际空白附件，因此预置项显示“尚未上传空白模板”，不会生成假文件。上传人需要模板维护权限；读取和下载需要模板读取权限。

保密资料不能默认对外可见。任务书的 6.11.6a/b/c 默认保密，6.11.6b/c 禁止外部查看；全部预置资料的默认对外可见均关闭。项目中的保密访问和分享范围由资料实例权限进一步约束。

## 输出时机的保存形式

| 类型 | 规则字段 |
|---|---|
| before_event | `timing_event` + `timing_offset_hours`，事件前 |
| after_event | 同上，事件后；车辆可用 `vehicle_arrival` |
| after_milestone | 到货签收、调试完工、上线运行、培训完成、验收、交付售后之一 + 小时 |
| weekly | `timing_weekday`，ISO 周一 1 至周日 7 |
| on_trigger | `trigger_type=accident/quality/member_leave` + 小时 |
| on_demand | 无截止规则字段 |
| lifetime | `timing_event=internal_kickoff`，全周期更新 |

不适用于当前类型的隐藏字段必须为空，避免表单切换后残留旧规则。服务端也校验枚举、星期、偏移、编号、重复项、同阶段分组和循环父链。项目实例和实际截止时间由 T22/T23 使用这些定义生成。

## 迁移和模板版本

Alembic `g3a21b000001` 接 `g3a20b000001`，新增 `document_requirements` 和 `document_template_files`。默认模板的数据库身份仍为 `template_id IS NULL`；两个部分唯一索引分别保证默认及自定义模板的编号唯一。

迁移把冻结的 56 行写入默认模板和当时已存在的模板。既有流程树、项目、采购项、准备项和参考文档不变。新模板复制所选来源的资料定义。预置仅执行一次；用户删改资料后，重启不会重新补回。

编辑、导入、删除、复制和发布共用模板事务锁。涉及源/目标时按稳定模板 ID 排序取锁；虚拟默认模板在 PostgreSQL 使用固定命名空间事务锁，在 SQLite 使用不改数据与时间的 UPDATE 取得写锁。拿锁后重新读取模板、父链与账号授权，避免两个管理员并发建立循环分组。

资料定义与流程树独立。保存流程树不会清空资料要求。复制模板会重新映射资料和分组 ID，并为每个空白文件复制独立字节。发布快照在既有 `snapshot` 阶段树旁，增加同级 `document_requirements`；旧快照形状保持。

空白模板文件独立于项目和任务，不创建假项目或假任务。资产不可变，保存 UUID 存储名、展示文件名、大小、类型、SHA256、上传人和时间。替换只建立新资产并改当前引用；移除引用或删除模板保留历史资产，以免损坏已生成项目或发布快照。后续存储清理必须把 `document_template_files.stored_name` 视作文件所有者。

新文件使用 0600 权限。数据库/审计提交失败会回滚新记录并清理本次新增文件；原文件保持。下载、复制和导出校验安全路径、非软链接、大小及 SHA256。文件仍位于完整加密备份覆盖的 uploads 目录。

## Excel 和 JSON 往返

Excel 保留“实施模板”表，新增“资料要求”表，另用隐藏“空白模板文件”表存文件元数据和不超过 30000 字符的 base64 分片。编号强制为文本，所有字符串按文字写入，不作为公式执行。切换工作簿当前选中页不会改变导入所用的实施模板表。

JSON 在原 `phases` 旁增加 `document_requirements` 与 `document_template_files`。父子关系使用父编号，文件使用便携键及字节，不信任源数据库 ID 或源文件路径。父编号和文件键仅接受空值或非空字符串，长度分别不超过40和36字符；Excel不把布尔或数字引用强转为字符串。导入到另一模板会建立新的资料、父级和文件 ID。

导入在写入前校验全部规则、父子关系和文件分片/大小/SHA256，随后流程树、资料定义、文件引用和审计统一提交。旧 Excel 没有“资料要求”表、旧 JSON 没有该字段时保留现有资料定义；显式空列表表示清空定义。

便携文件总字节受 10MB 限制，生成的 Excel 也不能超过当前 10MB 导入上限；超限会明确拒绝导出，避免生成无法导回的工作簿。大文件业务资料上传由 T25 另行处理。

## 模块和验证

- `services/document_requirements.py`：规则、默认模板身份、定义 CRUD、不可变资产与事务清理、复制、便携包校验。
- `services/document_requirement_workbook.py`：可编辑 Excel 定义及受限文件分片。
- `routers/document_requirements.py`：模板读取/维护权限声明和真实认证依赖。
- 种子冻结在 `migrations/v3_document_requirements_seed.json`，历史迁移不读取当前业务模型。

验证覆盖新库/旧模板迁移、SQLite/PostgreSQL、模型结构差异、全部条目、规则非法值、明确禁止/授予、跨模板父级、克隆文件独立性、发布快照、旧格式保留、JSON/Excel 文件字节往返、坏 SHA256 全部回滚，以及上传审计失败时原引用与原字节保持。
