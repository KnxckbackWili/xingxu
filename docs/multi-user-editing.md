# 多人编辑

目标：几个人同时改同一个项目，互不覆盖，不用刷新就能看到对方的修改。

## 一次写入

后端每次写入都在同一个事务里完成：

```
确认登录账号有效 → 确认项目存在且未删除 → 比对原值 → 写入 → 记操作记录 → 项目 rev 加 1 → 提交
```

被修改的那一行用 `SELECT … FOR UPDATE` 锁住，所以两个同时到达的请求会先后比对，不会都通过。

## 按格子比对

保存只发改动的那个栏目，并带上编辑开始时格子里的值（`from`）。后端只在当前值等于 `from` 时写入。

- 两个人改同一行的不同格子：各自的 `from` 都对得上，互不影响。
- 两个人改同一格：后到的返回 409，页面弹出“某某刚把这里改成了 ××”，选“用我的”就以对方的值为 `from` 再发一次，选“用对方的”就保留对方的值。
- 两个人改成了同一个值：不算冲突。
- 打勾是“设为做完 / 设为没做”，重复发送结果相同，不比对。

`from` 取的是**开始编辑时**的值，不是保存那一刻页面上的值。否则对方的修改在你打字时悄悄同步过来，你的保存就会不知不觉盖掉它。实现在 `frontend/src/components/Grid.tsx` 的 `useDraft`。

## 同步

- 项目页只用一个请求取回全部内容（`GET /api/projects/{id}`），响应带 `ETag`，值由 `rev` 决定。
- 页面每 4 秒带着 `If-None-Match` 再问一次。没变化时后端只读项目这一行就回 304；有变化才返回新内容。
- 页面切到后台时停止询问，切回来、恢复网络时立即问一次。
- 首页同理，版本由全部项目的 `rev` 合成。

实现在 `frontend/src/sync/useLive.ts`。两条保证：

1. **正在保存时不接收服务器副本。** 写入进行中拿到的副本可能是写入之前的，直接显示会让刚改的内容闪回旧值。写入结束后立刻重新取一次。
2. **正在编辑的格子不被覆盖。** 格子在获得焦点期间只显示自己的草稿。

没有用 WebSocket 或服务器推送：后端是多进程，前面还有反向代理，推送需要额外的中转组件。几个人、十几台车的规模，4 秒一次且绝大多数是 304 的询问负载可以忽略。

## 先显示后确认

改格子、打勾、新增、删除都先在页面上生效，再等后端回答（`frontend/src/sync/rows.ts`）。后端拒绝时页面恢复原值并提示。

新行的 `id` 由浏览器生成，网络不好重发时后端认得出是同一行。

## 删除

记录是软删除：`deleted_at` 有值就不再出现，30 天后由清理任务彻底删除。期间可以恢复：删除后底部的“撤销”，或操作记录里的“恢复”。恢复车辆时如果它的编号已被别的车占用，会提示先处理。
