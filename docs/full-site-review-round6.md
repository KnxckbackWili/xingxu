# 第六轮：按人的完整工作流程复核

## 结论先说

本轮基于第五轮交付 `cdb700d668`，继续审查跨功能的前置条件、操作顺序、撤回/返工、权限变化、多人竞争、失败重试和历史证据。确实找到此前未覆盖的实质问题，不能把前一轮测试通过等同于“所有流程都正确”。

本报告区分三件事：已复现并修复的缺陷、需要业务负责人决定的规则、环境仍无法验证的行为。**没有宣称所有角色×状态×输入×并发组合均已穷举，也没有宣称真实页面验收通过。**

## 典型完整旅程与修复

### 从建项目到进场、派工

- 准备评审、验收、归档和治理申请采用当前项目状态与权限重新校验，避免旧页面、锁等待和 ORM 缓存沿用旧条件
- 撤销准备完成清理旧完成信息；必需性提高、风险和日期变化不能继续沿用不适用的准备确认
- 个人日历不能绕过已完成/已归档保护，也不能给仅提醒的准备任务创建不可见的执行日程
- 同时提交负责人移交/治理申请不再产生重复待办；失去负责人身份后不能靠旧会话发起
- 请假/不可用汇总保留必要忙闲信息，私人说明按现有访问权限返回；日期、容量和预览冲突检查补齐

### 从现场报工到检查、交付、返工

- 报工成功→撤回→旧请求重试，不再把撤回数量重新写回；新 UUID 的真实新报工仍可提交
- 已实际完成 4.004 的任务不能把目标改为 4；车型数量变化同样不能把目标降至真实累计以下
- 普通任务编辑只能修改交付要求，不能伪造“审核通过”或冒用审核人；修改说明不再丢失原证据身份
- 问题指派人必须确实能进入该项目处理；前端下拉使用对应候选范围
- 检查重复通过不会悄悄替换原检查人，撤销失败状态保留审计
- 项目完成后安全复检失败或必需交付被退回，不能继续归档；已验证恢复验收、纠错、重新完成和归档路径
- 历史归档可解除锁定后纠错，不因旧证据不满足新门禁而永远无法恢复；重新完成和归档仍要通过当前门禁

### 从领料、移库到文件证据

- 同一次库存操作应答丢失后重试沿用 UUID，不再重复扣料；小数余额正常处理
- 从 10 件中领走 2 件，剩余 8 件保留原地点/保管关系
- 当前库存记录只有一个地点，部分移库不再假装把整批搬走，明确提示先拆分记录；异地部分入库不能悄悄合并地点
- 已被交付、验收或车辆记录引用的附件不能直接删除形成悬空证据；数据库失败不会先毁掉磁盘文件
- 共享收集箱、模板、任务和归档文件的存储所有权被保留；磁盘清理失败记录警告而不诱导重复业务操作

### 从模板、导入导出到历史保留

- 模板正常保存保留节点身份与参考文件历史，局部保存不会把未修改结构重建为新 ID
- 创建新项目的 JSON 导入保留目标、时区、检查定义等计划信息，清除属于原项目的附件和提交/审批身份，并展示警告
- 概览、看板、周报和 Excel 使用一致的质量进度规则；安全检查失败不再在一处显示 99%、另一处显示 100%
- 准时率按实际日程与工作日期计算，同名人员按 ID 区分，报告时间窗口采用项目时区
- 物理清理前使用独立的历史保留快照，保留验收、准备评审等业务事实和原身份，不复用面向新项目的简化导入格式
- 历史文件清单保存哈希与归属；授权角色可下载验证后的原文件。JSON 本身不包含文件字节，仍需完整系统备份
- 仍有关联私人日历的项目延后清理，不泄露日历内容，也不让它阻塞其他项目；所有者可清理自己的事件后继续
- SQLite 初始化迁移固定同一物理连接，提交/回滚后恢复外键约束；恢复失败的连接不返回连接池

### 从账号、AI 到中断后继续

- 不能停用或降级最后一个可用系统管理员
- AI 聊天不能调用未公开的合并/回滚写工具；后台作业重新核对当前权限和预算；过期结果不能覆盖终态
- 收集箱分类只使用可见项目，迟到分类结果不能把已归档文件变回可删除状态
- 钉钉签名避免重复编码；外部调用错误记录避免带出认证信息（本轮用模拟接收方验证）
- 开工编辑离开页面、前进/后退与取消使用统一未保存处理；任务版本快照和重试操作原始意图被保留

## 待业务决定，暂未擅自改变

已向用户提出前三项建议，等待确认：

1. 条件未满足必须显式风险进场并记录原因；目前保留原有兼容入口
2. 验收采用最新有效结果，不能拿后来已被否定的历史通过记录结项
3. 调试、试运行、验收由有权限的人确认推进，百分比只作为参考，替代现有 80/90/95% 自动推进

其他边界见完整矩阵，尤其是：

- 必需交付“已提交”还是“已审核通过”才能完成
- 多台车的质量记录按任务统一，还是逐车/逐批留档
- 已报满维修任务的车辆问题复发，应新建事件还是允许同事件下多轮维修任务；当前可用独立临时返工任务，不能擦除旧历史
- JSON 新建项目导入遇到原已完成/已归档状态，是否统一回到草稿；当前不等于完整历史恢复
- 单件工作占用多天时的计划数量与工期显示、分批下达和实质准备要求变更的重审规则

库存/车辆完整编辑尚未全域强制版本令牌、部分流程只有 API 没有完整页面入口等工程边界也单列在矩阵，不被写成“通过”。

- 252 个受保护 HTTP 操作匿名访问均返回 401，接口注册无重复；完整角色授权组合并未穷举

未运行真实 Docker、PostgreSQL 并发、NAS 断电恢复或外部 AI/通知服务。服务器 CI 是否可执行在发布时另行核对。历史上已经丢失的记录和文件不能被本轮修复自动补回。
