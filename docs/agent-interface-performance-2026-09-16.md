# Agent 接入、柔和配色与性能优化

## 使用上的变化

- 删除网页 AI 聊天页面、助手抽屉、导航及专用依赖。原聊天地址转到项目列表，避免旧书签报错。后台 AI 接口继续保留。
- 系统中的「Agent 接口」提供令牌管理、MCP 地址、可复制的 Hermes 配置和 HTTP 工具目录地址。
- 外部工具由15个增至22个，新增开工检查、模板列表与详情、团队、车辆、文件目录、项目动态。新增工具按账号项目范围和独立 scope 校验。
- 令牌创建默认只读，修复旧页面默认勾选合并 / 回退权限的问题；过期时间按明确时区提交。
- 全局采用灰绿底、浅米色内容区、深绿项目标题区；目录与工作区有明确底色区分，保留深色模式。
- 项目任务保留默认展开和直接入口。桌面行改用原生表格、进度和按钮，检查项可直接点击，支持键盘操作；手机保留卡片布局。

### 确认的原因与处理

1. 每个阶段都挂载完整 Ant Design 表格，反复测量滚动条；每行同时挂载多个样式组件、Tooltip、Progress。浏览器 CPU 剖析中滚动条测量与样式插入明显占用主线程。换成轻量语义表格与原生控件，保留全部任务及操作入口。
2. 模板读取在阶段 / 模块 / 任务循环中查库。现在按层批量读取并分组，返回字段与排序保持一致。回归测试限定实际 HTTP 端点查询数。
3. 外网主脚本原本未压缩：即使请求 `Accept-Encoding: gzip`，仍传输578897字节。新增静态资源压缩中间件，覆盖 `/assets/` 下 JS、CSS、SVG、JSON；保留哈希缓存、Vary和原始内容。API及流式响应不经过该中间件。

另两项假设未成为本次优化依据：全局可访问性监听没有在该场景的剖析中占主要成本；重复请求只在开发模式观察到，正式构建一次切换只有一次任务请求，因此保留开发模式的 StrictMode 检查。

## 后台实现

- HTTP 和 MCP 共用工具注册、输入 schema、执行逻辑与权限声明；同步数据库工作在线程池执行。
- MCP 采用无会话 JSON 响应；每次请求校验令牌与绑定账号。每个应用生命周期重建 SDK 的单次使用 session manager，修复此前重复启动时吞掉初始化错误的问题。
- Token 最近使用时间每5分钟更新一次，避免每次读取都写 SQLite；停用 / 过期仍每次检查。
- 文件目录有分页和上限，不暴露磁盘路径或下载凭据。不可见项目不返回数据。
- 非预期工具异常向调用者返回通用错误，具体异常仅写服务端日志。
