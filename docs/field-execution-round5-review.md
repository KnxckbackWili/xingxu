# 第五轮：现场执行与记录完整性

> 历史 QA 记录：接口、测试名和结果按当时源码保留，不作为 3.0.0 当前操作说明。原测试现按功能归入 `test_field_submission_integrity.py`、`test_inventory_transaction_integrity.py` 与 `test_field_operation_locking.py`；旧行为的保留、迁移或退役见[测试整理记录](test-organization-plan.md)。历史通过数量不代表新功能已复验或已部署。

## 已复现并修复

- 两个独立会话对目标 1 的同一任务各填报 1，原实现均成功并累计为 2。报工、修正、撤回现在按项目 → 任务的统一事务锁顺序执行，并在锁后重验项目可见范围、成员/能力和状态；手动完成/重开沿用同一顺序。
- 数量写入不再使用显示用的两位小数：原先 0.994 + 0.008 可以超过目标 1，0.006 - 0.008 可以变负。撤回也不能与既有修正组合出负数或越界；已完成项目的填报须恢复项目状态后才能撤回。
- 锁等待期间完成、归档、软删除或撤销项目权限，不能依赖旧页面/旧会话状态继续写入。现场检查、交付、问题、车辆、物品和附件写入口使用同一项目优先校验；没有改变全局可见性或能力定义。
- 同 UUID 重试继续幂等，不同 UUID 不互相吞掉。离线报工使用封装层 UUID；离线交付保留版本号。已经提交成功的离线凭证优先确认，不会因版本已经递增而误报失败；已成功报工/修正的重试也不会因项目随后完成而变成失败。
- 交付提交保留原有 required/doc_type/note 与未涉及的要求。空列表不再删除要求；删除和改名仍由任务编辑承担。整表携带未改动的已审项不再被当作重新审核，也不改写原审核人和时间。
- 已审核附件不能偷偷替换并保留原批准状态；新附件须重新提交。附件必须存在且属于本项目；空白或重名交付项拒绝，避免按任意同名项匹配。
- 今日任务返回任务与检查项版本，检查更新返回新版本，供前端避免过期页面覆盖新结果。
- 不适用后重新通过/不通过，会恢复适用并清除旧 N/A 原因。互相矛盾的三态请求拒绝；明确“不通过 + 未通过”不会被后处理清掉失败状态。检查写入后立即清理聚合缓存。
- 车辆问题重开即使未另带状态字段，也会重新显示至少“需关注”，不再显示无异常。
- 同一件库存不能被两个并发领料请求重复扣用；库存编辑、删除和流水按相同记录锁顺序串行，流水与余额同事务保存。
- 修正报工 UUID 长度收紧到数据库实际 36 字符，避免 SQLite 能保存而 PostgreSQL 拒绝。

## 定向验证

新增 `test_field_execution_round5.py` 共 50 项，包括真实 SQLite 双会话数量/库存并发、同/不同 UUID、在线/离线重试、交付材料与审核身份保留、三态切换和 9 类现场写入口的归档/撤权交错。独立验证另有 `test_execution_state_concurrency_round5.py` 的 20 项执行状态交错测试。

分次运行结果：

- 10 个既有相关测试文件：95 passed
- 最后一次定向组合：78 passed，1 个测试桩误伤锁前 SELECT 的失败；限定测试桩仅在 UPDATE 模拟锁超时后，该项单独 1 passed
- 随后补充的 4 个三态一致性测试：4 passed
- 差异空白检查、Python 编译检查通过

以上是定向、分次验证，完整最终快照由全量验证记录负责。测试使用合成 SQLite 数据和隔离网络，不涉及生产连接、上传、提交或部署。

## 未改变的规则与边界

未改变 80/90/95% 生命周期阈值、历史验收有效性、逐车/逐批质量模型、成员角色的既有检查权限或一般问题解决/验收政策。没有自动重开完成项目、改写历史报工，或为现场人员新增管理能力。

本轮无真实 PostgreSQL 运行环境。数据库行锁代码兼容 PostgreSQL 的 UPDATE 语义，但 PostgreSQL 竞争、死锁及吞吐仍需真实数据库验证；不将 SQLite 通过等同于 PostgreSQL 验证通过。库存/车辆长时间打开的编辑表单仍没有全域强制版本字段，本轮修复的是事务内并发余额/状态与已有版本路径，不宣称消除所有旧客户端的过期表单覆盖。
