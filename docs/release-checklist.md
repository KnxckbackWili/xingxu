# 发布检查清单

每次发布使用独立版本号（例如 `1.5.2`），禁止覆盖旧版本标签或只发布 `latest`。

## 发布前

1. 更新 `frontend/package.json`、锁文件、`.env.example`、Docker 构建参数和发布说明中的版本号。
2. 数据库变更必须可重复执行；破坏性变更需要独立迁移与恢复测试，不能只依赖启动时补列。
3. 运行后端完整测试、前端生产构建、Compose 配置校验和 Shell 语法检查。
   首次准备测试环境：`python3 -m venv .venv && .venv/bin/pip install -r backend/requirements-dev.txt`。
   发布门禁默认使用 npm 官方端点执行依赖审计；仅离线排查时可临时使用 `SKIP_AUDIT=1`，正式发布不得跳过。
4. 从生产备份恢复到临时环境，使用真实数据副本执行一次跨版本升级。
5. 扫描仓库，确认没有 `.env`、数据库、附件、备份、密钥或访问令牌。
6. 使用已经打开过旧版本的浏览器刷新一次，确认 PWA 自动取得新应用壳；再验证离线页面回退。

## 发布

1. 提交源码并创建不可变 Git 标签 `vX.Y.Z`。
2. 构建并推送 `linux/amd64`、`linux/arm64` 镜像，镜像标签使用 `X.Y.Z`。
3. 记录镜像 digest；NAS 的 `AGV_IMAGE` 优先固定到 digest，至少固定到版本标签。
4. 在空数据和恢复后的生产数据副本上分别检查 `/health`、登录、附件和核心业务流程。

## NAS 更新

1. 先确认最近一次异机备份可读取，并安排短暂维护窗口。
2. 更新源码标签或 `.env` 中的镜像版本，不直接修改 `data/`。
3. 运行 `bash docker/scripts/manage.sh update`。脚本会备份、保留旧镜像、部署、检查并在失败时自动回滚容器。
4. 登录核对版本与核心数据，保留升级前备份和回滚镜像至少 7 天。
5. 每季度执行一次完整恢复演练；未经演练的备份不能视为可靠备份。

自动发布入口：登录 Registry 后执行 `bash docker/scripts/publish.sh`。脚本要求工作区干净且 `vX.Y.Z` 指向当前提交，并在推送前运行完整发布检查。
