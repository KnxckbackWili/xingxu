# 阶段与工作项

项目计划直接维护阶段下的工作项。模块名称保留为分组标签，原模块表仅是来源，新增工作及模板生成不创建业务模块。工作说明、参考文档、检查要求和原任务 ID 保留。车辆工作须由计划维护者明确关联当前项目的真实车辆进度环节；未映射来源不会按名称猜成默认五步。

非车辆工作只有完成和未完成。完成、重新打开都要求理由，使用工作版本号防止旧页面覆盖。登记者和登记时间是操作记录，不代表历史实际执行者或实际发生时刻。车辆工作从真实矩阵读取完成数量，不能通过工作项的直接完成跳过逐车登记。检查仍独立：安全项必须通过、必需待检项不能覆盖；负责人对普通失败项的覆盖只对应当时明确确认的检查 ID、版本和失败理由。检查撤销或理由变化会使当前完成资格重新核对，原完成记录不被擦除。

计划维护仍需项目计划权限；完成登记仍需填报权限及当前项目成员/负责人资格。现场登记只允许 `executing`、`acceptance`，项目锁后重读权限和检查。暂停、结束及归档状态不能通过旧工作接口继续维护定义。写入使用共同项目锁，批量车辆写入继续由矩阵服务原子校验。

## 原工作保全

增量迁移 `g3a34b000001` 接 `g3a53b000001`，在线运行，离线 SQL 在任何 DDL 前明确拒绝。原 `tasks.module_id`、目标数量、单位、耗时、原报工和检查行保持不变；工作直接新增 `phase_id`、`group_label`、`scope_conditions` 和只读 `legacy_work_snapshot`。项目任务引用共享模板阶段时，新建项目自己的阶段并保留原阶段来源。原阶段、模块和任务行不删除。

迁移快照记录原任务描述、数量口径、目标、单位、排序、安全标记、依赖、车型、来源 ID、完整原手动完成信息及覆盖版本；另记录原模块/阶段标识、原数量合计和原报工条数。非车辆旧工作仅在原正目标已达到且质量条件满足，或全部普通检查原已不适用时转换为完成；不猜操作者或实际时间，转换审计标明历史依据。原本已手动完成的事实不改。原项目准备工作保留在只读“历史准备工作来源”，不重新进入资料或实施流程。

`GET /projects/{id}/work-items/{task}/history` 返回原数量、原 UUID、日期、操作者和原备注，仅作追溯。旧报工 UUID 的精确重试可以只读确认，修改原载荷或未知 UUID 返回 409；同步结果是 `deferred`，不会消费原队列、换 UUID 或制造新的完成事实。旧已提交数量也不能通过撤回改写当前布尔资格。

## 复制、导入与交付

模板选择使用工作项 ID，旧模块 ID 仅作只读来源选择适配。模板复制、JSON 导入及项目克隆保留阶段、分组、说明和检查定义，并重置新项目的完成、通过/失败、操作人和时间。便携原执行来源仍在 `portable_unverified_snapshot`，不自动成为新项目资格。系统一致备份、项目回收站加密备份和还原则完整保留原 ID、原表字段和真实资格。交付仍保持 T27 六表，`execution_evidence` 保留新工作字段及原数量来源，不恢复旧数量业务表。

原阶段名“系统联调”“试运行”在工作项读模型中显示为“联调工作”“试运行工作”，新生成阶段使用新名；原阶段行及便携来源原名保持可核对。

周计划在 T40 接入；本任务保留旧日程只读显示与周计划链接，后续按周迁移不会把计划负责人推定为实际执行者。

## 验证边界

`test_work_items_t34.py` 覆盖完成理由/CAS、真实车辆检查、准备态拒绝、原 UUID 保全、普通失败精确覆盖、检查撤销后资格变化、历史准备只读、模板/JSON/克隆重置、原来源快照及 PostgreSQL 双会话新读。`test_work_items_migration_t34.py` 按命名增量读取真实父链，验证原字段、原报工/检查行、重复启动、单 head、外键和模型差异。

前端旧“修改目标数量”和新建按量填报测试已按退休产品语义删除；权限撤销、版本冲突、重复点击、原队列不改、账号/项目切换、问题 UUID、附件部分失败及维修草稿等场景改为新的工作项或原问题/维修契约继续验证。

未被任何产品页面引用的旧 `StartupWork` 数量向导和 `taskPending` 数量待办工具及其专用测试一并退役。人员/日程中的旧按日查询由 T33/T40 替换，本任务不把只读历史 ScheduleEntry 恢复成模块业务。
