# 关键事件与车辆到场

新建项目和项目设置可以填写调度平台（NDC、GRACE、集成）及内部启动会、发车、全部到场的计划日期。概况中的关键事件时间线同时显示到货签收、调试完工、上线运行、培训完成、项目验收、交付售后。计划日期可以调整；已有准备要求日期和日程不会自动平移。

拥有项目资料修改权限的人员可登记事件实际发生的日期和时间。输入与显示采用项目现场时区，数据库统一保存 UTC。更正会保留操作记录；清除已登记实际时间必须填写理由，原值和理由均可审计。登记关键事件不会自动改变项目状态。

车辆页可选择多台车辆，一次登记共同到场日期，也可分批登记。拥有计划管理权限的人员可以操作；清除已有到场日期须填写理由。系统逐个核对每种计划车型的数量：所有车辆必须完整建档、关联正确车型且全部已有到场日期，才以最后一台的到场日期形成“全部到场”。零台、部分建档、额外未匹配车辆或车型数量不符均不代表整批到齐。调整车型数量、新增建档或清除到场记录后，会自动重新核对并审计汇总变化。

“全部到场”的输入只有日期，因此时间线只展示日期，并标明“按逐台到场日期汇总”。API 的 `actual_precision=date` 与 `actual_date` 说明该精度；`actual_at` 是该日期在项目时区零点对应的 UTC 锚点，供截止规则使用，不能解释成精确到场时刻。其他人工事件可登记真实业务日期或带时区的实际时分，日期不补造成午夜时刻。

## 旧数据与备份

增量迁移 `g3a20b000001` 接在 `g3a03b000001` 后：原 `projects.planned_entry_date` 转为发车计划，原 `entry_plan.entry_date` 转为全部到场计划。原字段和值保留，实际发生时间均保持未知。无法识别的旧日期会中止并回滚迁移，要求先核对原始资料，不会猜测日期。该数据转换须在线执行；回退需恢复升级前一致备份。

旧 `planned_entry_date` 和 `entry_plan.entry_date` 仅保留读取，新写接口明确拒绝更新，计划统一通过 `event_plans` 或事件接口修改。项目的其他交接信息仍可编辑，保存时保留旧日期原值。JSON、Excel 和项目删除保全备份覆盖新事件、平台与逐台到场；旧 JSON 导入按同一规则转换计划，新的 JSON 导入不会用旧只读值覆盖已清空的新计划。项目克隆保留平台与计划日期，实际发生记录保持空白。

## 接口

- 项目创建/修改：`dispatch_platform`，以及 `event_plans` 字典（事件键到日期或 null）。
- `GET /api/projects/{id}/events`：九个关键事件、车辆汇总、项目时区和版本。概况聚合接口同时返回这些数据。
- `PUT /api/projects/{id}/events/{event_key}`：`planned_date`、`actual_date` 或带时区的 `actual_at`、`note`、清除理由 `reason`，要求 `project.update`。全部到场实际值不能人工修改。
- `PUT /api/projects/{id}/vehicle-arrivals`：`unit_ids`、共同日期 `arrived_at`（清除为 null）、`reason`，要求 `project.manage_plan`。跨项目或失效车辆会令整批请求失败，所有到场记录保持原值。

所有写入在项目锁和现有项目写保护下执行，并调用 `log_change()`。接口不执行项目状态自动推进。
