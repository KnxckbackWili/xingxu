# 周计划与原按日来源

周计划按真实工作项和周组织，负责人可多人。车辆工作可以选择全部适用车辆、车型或明确实车批次，填写本周完成的正整数台数；非车辆工作只安排完成状态。选择“进行中”不填目标台数，也不判逾期。负责人仅代表计划安排，实际执行人和协助人由现场操作另行登记。

## 编辑、发布与初稿

项目“计划 → 周计划”支持选择周和阶段、编辑格子、取消后明确恢复，以及只发布选中的格子。发布后的格子可直接调整，原、新负责人收到变更通知；未发布格子对普通成员不可见。写入使用现有 `project.manage_schedule` 系统与项目能力，工作定义仍需独立的工作维护能力。保存、发布、认领和排期设置均在项目锁后重新核对身份、成员和版本，迟到表单返回 409。

“生成初稿”先读取来源可核对的建议，再预览确认，始终生成未发布格子，不自动指派人员。默认建议只识别冻结标准工作定义的阶段 ID 或其来源快照，不按阶段名称、当前序号或资料阶段编号猜测。标准进场准备工作对应发车前窗口，至少倒推一周；标准现场工作按顺序分配到全部到场至计划验收日（缺少时采用项目计划结束日）的整周窗口，窗口短时允许阶段重叠。这是可调整的计划建议，不代表工时、实际日期或验收资格。自建、混合或来源缺失的阶段必须人工明确规则；关键日期缺失时不给猜测计划周。

人工规则可选择发车前或到场后及非负整周偏移，不使用耗时学习、工期倍率、按日数量或自动负载分配。已有工作计划不被初稿覆盖。预览令牌绑定当前项目、工作、关键日期及已有计划；任一来源变化后须重新预览，原输入由页面保留。

项目设置中的“排期设置”维护休息方式、指定休息日和是否避开节假日，使用专用的周计划授权接口。已有周格不会因设置变化自动移动。表头注明官方节假日、调休补班和项目休息日；未发布年度数据明确显示缺年，不当作全年无假期。

## 完成、逾期与核对

车辆目标只读真实矩阵和已确认的历史迁移完成凭证，并复核当前逐车、任务级必需/安全检查。手动工作完成、负责人或计划台数不能覆盖安全检查，未知车号凭证也不声称逐台核验或知道实际完成日期。非车辆工作读取布尔完成及其当前检查资格。

同一工作、同一选车范围的已发布完成目标按周累计：第一周 5 台、第二周 5 台，需要当前累计达到 10 台，不能把同一份 5 台重复视作第二周新增完成。只在周日已经过去、格子已发布且目标可核对但未满足时标逾期。“进行中”永不逾期；数量未知、小数目标或环节来源不一致显示“待核对”。原计划含NULL或非有限数值时，车辆和非车辆都不能被当作已完成或逾期；已知部分和单列保全，不把未知量当0。

车辆数量、适用范围、选车身份或计划目标变化时，在周表及概况提示核对。重叠选车范围会警告，系统不自动修改目标或制造完成事实。人员不可用和同周跨项目安排提示人工确认；无权限查看的项目名称及不可用私密原因不泄露。

无负责人且已发布的格子可由当前有填报权限的项目成员明确认领，竞争认领只有一个版本成功。本人计划只包括被明确分配的格子，可认领格子单列。移除人员或移交项目时，未完成的已发布周计划须已有仍合格的共同负责人，或先明确改派、取消；原按日日程不会永久阻挡离场。

## 导出与保全

所选周、阶段和当前可见范围可以导出 Excel；页面提供 PNG 以及浏览器打印为 PDF。Excel 有“周计划”“核对提示”“原日程来源”三页，明确草稿、发布、未知和迁移凭证，不把项目名或备注解析为公式。打印为 PDF 使用浏览器，不依赖服务端 PDF 接口。

在线 Alembic 修订 `g3a40b000001` 按工作、周、原发布状态和取消状态汇总旧 `ScheduleEntry`。全部原行保持不变，每格只读 `source_metadata.original_entries` 保存逐条全部字段、原日期、负责人、计划量、发布状态、备注、版本和 ID；`original_planned_sum` 用十进制字符串保全汇总。不同发布状态不混成已发布，发布时间和发布人未知时仍为 null。原整数车辆目标可供核对，小数保持原值并标记待核对，不猜整数台数。原NULL与非有限值保留未知，完整和为null，有限部分另存known_planned_sum，unknown/null/invalid_quantity_count分别保留来源数量。任何未知组都不生成确定台数。迁移不改实际完成、检查、原数量报告或原任务目标；失败时 schema、版本和原数据一起回滚。此数据迁移拒绝离线 DDL，降级须恢复一致备份。

旧按日生成、重排、范围、工期和日历写入口返回 410。原 `ScheduleEntry`、工期覆盖和策略仍作为只读来源保全，服务不重新运行原排程算法。便携 JSON 导入和克隆不建立活跃日程、工期策略或已发布周计划；原计划完整保存到 `portable_unverified_snapshot`，新项目需重新确认范围、负责人和发布，不能继承原项目完成资格。项目加密保全、永久删除备份及系统一致备份保留完整 `WeeklyPlanCell`、原日程和原策略记录。

## 接口与服务接缝

项目统一入口 `/api/projects/{id}/weekly-plans`，支持 GET/POST、`PUT /{cell_id}`、`POST /publish`、`GET /draft-rules`、`POST /draft/preview`、`POST /draft`、`GET/PUT /settings`、`POST /{cell_id}/claim`、`GET /legacy-source` 和 `GET /export/excel`。读窗口按项目时区周一至周日规范化；查询最多 104 周。保存必须携带当前版本，工作 ID 不可通过格子更新替换。

本人读取 `/api/worker/weekly-plans?scope=mine` 返回本人已发布格子和单列 `unassigned`；团队读取仍受项目可见性与调度能力约束。人员页、周报和工作台复用 `services.weekly_plans.select_cells`、`serialize_cell`、`completion_fact`，不从计划负责人或旧数量报告推导实际执行人。

增量 `g3a40b000002` 接在T33后，为历史未知意图增加独立当前核对标记，并兼容已应用早期隔离QA的g40。原来源、负责人、周和实际事实不改；若旧QA曾将未知量误当0生成确定目标，修订保守纠正并系统审计。待核对格只有在编辑时明确勾选确认、填写理由并选择完成目标或进行中，才清除当前核对状态；仅补备注、改负责人或版本更新不会清除未知。原来源JSON仍只读，后续人工确认不回写原量。
