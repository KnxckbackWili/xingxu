# 周计划与原按日来源

周计划按真实工作项和周组织。车辆工作可以选择全部适用车辆、车型或明确实车批次，填写本周完成的正整数台数；非车辆工作只安排完成状态。选择“进行中”不填目标台数，也不判逾期。实际谁做了由现场登记另行记录。

## 编辑与按规则生成

项目“计划 → 周计划”可以选择周和阶段、编辑格子、取消后明确恢复。没有草稿和发布之分：格子一保存就是计划，所有能看项目的人都能看到，之后可以直接调整。写入使用 `project.manage_schedule` 能力；保存和排期设置在项目锁后重新核对身份和版本，迟到表单返回 409。

“按规则生成”先读取来源可核对的建议，预览确认后直接生成计划格。默认建议只识别冻结标准工作定义的阶段 ID 或其来源快照，不按阶段名称、当前序号或资料阶段编号猜测。标准进场准备工作对应发车前窗口，至少倒推一周；标准现场工作按顺序分配到全部到场至计划验收日（缺少时采用项目计划结束日）的整周窗口，窗口短时允许阶段重叠。自建、混合或来源缺失的阶段需人工选择规则；关键日期缺失时不给猜测计划周，预览里说明原因。

人工规则可选择发车前或到场后及非负整周偏移，不使用耗时学习、工期倍率、按日数量或自动负载分配。已有工作计划不被覆盖。预览令牌绑定当前项目、工作、关键日期及已有计划；任一来源变化后须重新预览，原输入由页面保留。

项目设置中的“排期设置”维护休息方式、指定休息日和是否避开节假日。已有周格不会因设置变化自动移动。表头注明官方节假日、调休补班和项目休息日；缺少年度数据的周标“缺节假日数据”。

## 完成与逾期

车辆目标读真实矩阵的逐车完成情况；非车辆工作读完成标记。同一工作、同一选车范围的完成目标按周累计：第一周 5 台、第二周 5 台，需要累计达到 10 台，不把同一份 5 台当作第二周新增完成。只在周日已经过去、目标未达成时标逾期；“进行中”永不逾期；数量未知时不判逾期。

周计划只写“这周做什么”，不分配负责人，也不出“需要核对”的提醒：谁做完谁在本周页登记。

## 导出与保全

旧按日生成、重排、范围、工期和日历写入口返回 410。原 `ScheduleEntry`、工期覆盖和策略仍作为只读来源保全，服务不重新运行原排程算法。便携 JSON 导入和克隆不建立活跃日程、工期策略或周计划；原计划完整保存到 `portable_unverified_snapshot`，新项目重新安排。项目加密保全、永久删除备份及系统一致备份保留完整 `WeeklyPlanCell`、原日程和原策略记录。

## 接口与服务接缝

项目统一入口 `/api/projects/{id}/weekly-plans`，支持 GET/POST、`PUT /{cell_id}`、`GET /draft-rules`、`POST /draft/preview`、`POST /draft`、`GET/PUT /settings` 和 `GET /export/excel`。读窗口按项目时区周一至周日规范化；查询最多 104 周。保存必须携带当前版本，工作 ID 不可通过格子更新替换。

本人读取 `/api/worker/weekly-plans` 返回可见项目的计划格；本周页、周报和工作台复用 `services.weekly_plans.select_cells`、`serialize_cell`、`completion_fact`，不从计划推导实际执行人。
