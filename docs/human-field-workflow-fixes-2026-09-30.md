# 现场人工作业闭环修正（第二轮）

## 本轮边界

数量报工与质量确认分别保留，不改写历史数量；不改变 80/90/95% 阶段阈值，也不更改历史验收通过记录的有效性政策。本轮没有新增车辆级检查数据模型，现有检查仍属于任务。

## 已修改

- 适用的必查项尚未通过时，任务进度封顶 99%，最终完成和交接清单按任务真实数量与检查状态判断；非必查普通项目未检查不阻塞，明确不通过仍阻塞。
- 今日页面把数量报齐标为“数量已报齐”，有待检查项时明确显示数量，不再称“全部完成”。任务手工完成的普通检查覆盖与后端一致。
- 保留 PM 手工完成对数量和普通检查的既有覆盖；安全检查不能借此绕过。新直接完成请求在安全检查未通过时给出具名错误。历史手工完成标记、报工记录和项目状态原样保留；历史任务若安全检查未通过，进度/交接会揭示待处理状态，不会自动重开已完成或已归档项目。
- 被指派的现场工程师可开始处理并提交处理措施与验证结果，沿用后端既有权限。失败保留输入；版本冲突必须刷新查看最新状态后再提交，改派或已关闭后不会继续提交。
- 已完成项目问题重开时提示 PM 恢复返工步骤，并通知项目经理；不会自动改变项目状态。重开递增版本，避免旧页面覆盖重开结果。归档仍只读。

## 人工流程建议

PM 下达人员、时间、数量与检查标准 → 工人报告实际工作量 → 检查人确认质量 → 问题处理人记录处理与验证结果 → 报告人或指定复核人复验 → PM 确认里程碑和交接 → 客户验收 → 完成与归档。

数量报齐不等于质量通过；问题解决不自动替代检查确认；返工不应虚增原完成数量。

## 验证

本轮新增后端回归覆盖普通必查、可选项、安全项、历史手工完成、安全失败、交接待办及已完成问题重开通知。新增前端回归覆盖数量报齐但检查未做、本人问题处理、失败草稿保留、版本冲突刷新和完成项目返工提示。
