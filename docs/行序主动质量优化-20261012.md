## 实际修复

| 触发条件 | 修复后的行为 |
|---|---|
| 工作时帮助提示自动弹出 | 帮助仅在用户主动打开时显示；Escape 或关闭按钮收起后回到帮助按钮，切换提示内容时收起旧提示。 |
| 通知难以点击、键盘访问中断，或加载失败被当成没有通知 | 点击打开通知，Tab 可继续访问通知和操作，Escape 关闭并回焦。加载失败显示错误与重试，刷新失败保留并说明上次内容；全部已读失败给出提示。旧账号的迟到响应不改动新账号通知，手机浮层随视口收窄并调整位置。 |
| 项目进度接口失败，或单个个人演示的进度请求失败 | 未取得有效数据的项目显示“进度暂不可用”，不冒充 0%，不计入进度筛选；项目仍可打开，并显示受影响数量与重试入口。单个演示失败只影响自身；真实 0% 仍属于未启动。 |
| 消息标记已读后，较早的列表 GET 才返回 | 全部、单条和批量标记成功后，仍在进行的旧读取不能把消息改回未读；按当前筛选取得新结果。没有在途读取的全部视图保留原分页和本地更新。 |
| 日程只有已跳过的未确认记录，或保留的日程数据重新加载失败 | 已跳过记录保留在历史中，不计入待发布数量；没有有效待发布记录时不提供空发布。加载或刷新失败时暂停发布，成功重新加载后再恢复；超周期确认同样受保护。 |
| 开工清单保存期间离开页面或切换项目 | 旧保存的迟到成功、失败和回调不再改动新页面的填写、忙态或导航；新项目独立填写和保存。 |
| “今天”数量提交结果不确定，刷新后剩余数量已为 0，或离线队列、登录账号发生变化 | 保留本次完整填报内容及记录标识，锁定数量修改，提供“重试本次填报”；剩余为 0 仍可确认原提交。离线时确认同一记录已实际进入当前账号队列后才交接；未确认保存或账号绑定变化时保留原填报，不误报交接成功。401/403 等不能确认记账结果的失败保留原记录标识，数量修正入口也遵守账号与重试保护。 |
| 工作详情数量入口遇到账号切换或 4xx 错误 | 发送前校验当前用户与离线账号绑定一致；绑定不符不发送，保留草稿和待确认内容。仅明确业务拒绝 400/422 允许修正后产生新记录标识；401/403/404/408/429、网络错误和 5xx 保留同一次提交，恢复后重试。 |

后端本轮仅更新 `backend/app/config.py` 的默认版本，前端包元数据与 Dockerfile 同步为 2.3.8；未新增本轮后端测试结果。历史后端验收不计入本轮。接口和数据库结构没有在本轮改动。
