# 第六轮前端流程与真实浏览器验证记录

日期：2026-10-01。范围：当前隔离源码快照；合成演示数据；不连接生产、真实账号、外部 AI/通知服务，不创建隧道，不部署。

## 验收结论与边界

**本轮没有完成真实浏览器 UI 验收。实际成功渲染的应用页为 0，实际 UI 旅程为 0，实际截图为 0。**

下面的代码修复和 Vitest/jsdom/路由器回归不能代替桌面、手机、触屏、PWA、打印的真实验收。没有把浏览器未执行项记成通过。

## 实际尝试过的运行路径

1. 使用既有 Python 虚拟环境，以独立 `DATA_DIR`、SQLite、`SEED_DEMO_USERS=1` 启动 FastAPI。禁用 scheduler，继承测试专用外部 socket 禁止器，不读取生产配置。
2. 云浏览器（dot 的云浏览器）打开 `http://127.0.0.1:8766`，返回 **`net::ERR_BLOCKED_BY_CLIENT`**。已查阅工具支持的排障说明，未通过替代域名、代理或隧道绕过。
3. 发现受限命令各自处于独立进程/网络命名空间；另一次命令的 curl 无法访问前一次命令启动的端口。这是环境约束，不能通过修改 Vite proxy 就修好。
4. 将本地服务和预装 `/usr/bin/chromium` 放在同一个 Node/Playwright 自动化测试 harness 中：服务器健康检查成功；浏览器在启动时崩溃：

   `FATAL:chrome/browser/process_singleton_posix.cc:297 Check failed: . socket() failed: Operation not permitted (1)`

5. 对同一个隔离 harness 使用工具支持的权限申请运行一次，仍得到相同的 Unix socket 拒绝。随后停止该路线，没有禁用主机限制或继续尝试绕过。
6. 测试 harness 的 finally 会关闭浏览器与 Python 服务。Playwright 只装入独立测试目录，未增加项目依赖或 lockfile 改动。配置仅允许 loopback 页面请求。无真实应用截图生成。

可复现 harness 与进程日志保留在交付工作区的 `test-env/round6-ui/`。项目交付代码不依赖该临时目录。

## 流程修复

### 开工安排未保存输入

- 原代码只保护部分项目菜单/步骤按钮，全局导航、程序导航与浏览器 Back/Forward 可直接离开。
- 应用入口改用 React Router 数据路由器；开工页用原生 blocker 集中判断路径/查询参数变化。
- 取消保留当前输入；放弃后执行所选导航；连续点击只显示一个决定。
- 保存时同步更新脏状态引用，保存并继续不再触发旧警告；无改动时不阻挡只读浏览。
- 刷新/关闭页面保留 beforeunload 提示。不能据此声称已经实测浏览器对该提示的呈现方式。
- 开工排程统计排除 `status=skipped` 的已取消安排，避免误锁目标量或误标已下达。
- 回归使用与入口相同的“通配数据路由根 + 子 Routes”拓扑，覆盖全局链接、查询步骤、Back/Forward、取消、重复点击、保存同步清脏与 beforeunload 清理。

### 问题上报、指派与共享工作区

- 处理人候选改为服务端 `/projects/{id}/issue-assignees`，与实际可访问/可处理范围一致。加载失败明确报错并禁用，不回退为全员。
- 本项目中被指派给当前账号的问题，可在共享工作区开始/解决，不再误要求全局 PM 管理能力；仍不能自行改派或关闭复核。
- 归档项目隐藏新增、导入、指派、状态修改入口，保留读取/导出。
- 指派与状态提交串行，进行中不能关闭；409 后重新读取当前问题供明确重试。
- 读取按项目/请求序列隔离，较晚的旧请求不会覆盖新列表。
- 质量问题文件导入增加提交锁。

### 任务编辑、完成量修正

- 编辑任务提交打开时的 version，只提交交付要求 `name/required/doc_type/note`，不回传审核人、审核状态、文件身份等证据字段。
- 保存、生成、直接完成与完成量修正增加同步提交锁；提交中禁止关闭相应表单。
- 完成量修正网络/5xx 失败后冻结原数量/原因与 UUID，重试沿用原请求，不能用旧 UUID 偷换意图。
- 关闭再打开恢复原待确认操作；以账号、项目、任务隔离的 sessionStorage 记录支持同标签页换页/刷新后恢复。浏览器存储不可用时保留当前组件内的保护；不承诺跨设备、跨标签页或清除站点数据后仍能恢复。
- 明确 4xx 拒绝后允许修改再提交；确认成功后清除待确认操作。
- 今日现场页的管理修正入口也采用同样的冻结与重试规则。

### 物品流水

- 新增 `client_uuid`，接通后端幂等回执。`accepted:false` 表示原操作已经确认，并非需要再扣一次。
- 结果未知时冻结完整动作（数量/位置/人员/时间/说明）并保留操作编号；同账号、项目、物品隔离恢复。
- 已确认保存后列表刷新失败只提示刷新读取，不把已保存动作重新放回提交队列。
- 整条台账位置转移默认带当前全部数量并只读，明确提示部分移动先拆分记录。领用/消耗/归还的经手人与去向仅记录本次流水，不把剩余库存位置/保管人覆盖。

### 报表与个人日程

- 周期报告人员统计按服务端 `user_id` 作为身份键，同名不同人保持独立。
- 人员不可用摘要在隐藏原因时显示“不可用”；排程冲突提示不依赖私密原因字段。
- 个人任务日程对 completed/archived 项目显示只读；新增任务日程排除终态项目；个人临时事项保留原来的项目选择规则。
- 个人日程新增/修改增加同步提交锁，进行中不能取消；切换项目时忽略旧任务请求。
- 修正既有团队月历测试的跨月 fixture：下个月响应必须给出下个月日期，不能偶然依赖“今天”仍在下个月 42 格内。页面实现没有因此放宽日期范围。

### JSON 创建新项目

- 导出页快捷导入也先调用预检，展示错误/警告，再明确确认创建；取消预检不写入。
- 展示后端“旧附件和审核状态不能作为新项目证据、交付要求需重新提交”的提醒。
- 确认串行、失败保留预检内容；创建成功后使用返回的新项目 ID 导航。
- 本轮没有自行决定历史终态项目导入后应重置成哪种生命周期状态；该政策另行确认。
