# AGV 项目管理系统：界面与产品逻辑整理

## 核心工作流

项目内功能按实施过程归属，避免同一内容散落在多个页面：

1. **项目总览**：项目健康、当前阶段、近期风险和关键动态。
2. **执行计划**：阶段、模块、任务、目标量与检查项。
3. **项目日程**：排程规则、日历、甘特图和任务下达。
4. **项目问题**：问题上报、分类、指派、处理与关闭。
5. **交付与验收**：交付物、项目文件和验收归档。
6. **项目动态**：完整变更记录和周期报告。
7. **项目设置**：基本信息、车型、成员和任务结构调整。

## 统一规则

- 同一页面只保留一个主操作入口；上下文页已有主按钮时，项目头部不重复展示。
- 快捷入口必须打开真实功能页，不能静默回落到项目总览。
- 空状态只提供当前可执行的下一步，不同时展示“生成”和“重新生成”。
- 状态切换存在风险时，取消确认不得改变项目状态。
- 风险摘要同时纳入逾期任务、未解决问题、准备逾期和准备阻塞。
- “任务数”和“完成量”分别命名，不用一个数字同时表达两种口径。
- 项目模板预览只展示会实际生成的模块；可选模块只显示数量和后续入口。
- 桌面端项目列表默认使用表格，移动端默认使用卡片，并记住用户选择。
- 项目设置不重复承载归档、变更记录和周期报告。

## 本轮走查发现并修复

- 系统默认模板在创建项目时重复出现。
- 项目设置、项目文件和导出入口路由存在“按钮可点但页面未渲染”的情况。
- 页头把当前阶段再次标成下一里程碑。
- 新项目存在准备风险时仍显示“暂无待处理事项”。
- 问题页同时出现两个“上报问题”按钮。
- 空日程同时展示重新排程、确认下达和自动生成日程。
- 日程全部下达后仍显示确认按钮；空甘特图未显示正确空状态。
- 状态风险确认弹窗出现前，后端已经提交状态变更。
- 项目设置重复包含归档清单和变更记录；总览重复包含周期报告。
- 创建弹窗混合展示已选和未选模块，且信息密度过高。

## 样例项目

本轮在本地开发数据中创建了“长春汽车工厂 AGV 搬运项目”，使用系统默认模板，并启用新制造车辆、WMS/MES 和自动充电条件。该项目用于走查总览、执行计划、日程、问题、交付和动态页面。
