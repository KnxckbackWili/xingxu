# 项目模板：段落 + 一件事一行

模板只有两层：**段落**和**事项**。一个车型一个模板，不设车型的是通用模板。

## 段落

段落的标题自己定，可以加、删、改名、拖动排序。

每个段落放在公司资料阶段 4–9 中的一个，决定这一段要交的文件在哪个门禁前核对：

| 段落所在阶段 | 这一段的必交文件 |
|---|---|
| 内部启动会（4） | 开始实施前交齐 |
| 发车前（5） | 发车进场前核对 |
| 实施（6）、验收（7） | 项目完成前交齐 |
| 交付（8）、全项目周期（9） | 归档前交齐 |

多个段落可以放在同一阶段，比如“到货与单车调试”“系统部署与联调”“试运行”都在实施阶段。段落标题就是项目计划里的分组名。

## 事项

每一行是一件事，分三种：

- **工作**：要做的事，带入项目计划。
  - 可以勾“每台车各做一次”，在车辆进度表里逐车登记。每个这样的事项就是一个车辆环节，不用另外维护环节列表。
  - 可以写检查要点，每条可标“安全”或“选做”。
  - 可以上传参考文件。
- **资料**：一组要交的文件，例如“每周资料”“交付资料”。
- **采购**：要买的东西，写数量、单位和规格；任何段落都能放。开工前的车辆和充电桩放在启动准备，现场坏了要换的备件放在试运行。

任何一行都可以挂“要交的文件”。每份文件可以设置：
- 编号：不填会按所在阶段自动编号，如 6.12。
- 是否必交、每台车一份。
- 什么时候交：事件前后、节点完成后、每周、发生情况后、项目期间。
- 只用于某个调度平台。
- 保密和外部查看。
- 空白模板文件。

文件编号在模板内唯一。公司编号（如 6.10.4 培训记录表）可以放在任何阶段的段落里，核对时按所在段落的阶段。

勾了“可选”的事项，新建项目时列出来让人勾选。勾选的才带入，包括它的工作、要交的文件和采购；不勾就不带入。

## 复制、导入导出

- **复制为新模板**：整份复制，空白模板文件和参考文件各自独立一份。
- **从其他模板复制**：勾选另一个模板里的几件事复制过来。默认放到同名段落，没有同名段落就放到最后一段，也可以指定段落。编号冲突的文件会自动换一个空闲编号。
- **Excel**：导出一个表格，各工作表如下：
  - 「事项」：一行一件事。
  - 「文件」：按编号写交付规则。

  改完导回来会整体替换这个模板。名称相同的事项、编号相同的文件，原来的空白模板和参考文件都保留；表格有错时整份不导入，原模板不变。

## 通用模板的默认内容

默认约 20 件事、9 个段落，公司 53 份资料全部挂在对应事项上：

- **工作**：内部启动会、场地勘测、到场点检（每台车）、单车调试（每台车）、服务器与网络部署、地图与站点、系统联调（每台车）、上线运行（每台车）、操作与维护培训、最终验收。
- **可选工作**：WMS/MES 对接、电梯/自动门对接、PLC 对接。
- **资料**：发车与进场资料、交付资料、每周资料、发生时提交、全程更新资料。
- **采购**：AGV 本体、自动充电桩、网络设备（可选）、安全围栏（可选）、备件（坏件更换，可选）。

车辆环节沿用原来的 key（到场点检 `arrival_inspection`、单车调试 `single_commissioning`、系统联调 `system_integration`、上线运行 `go_live`），已有车辆进度不受影响。

## 实现

`template_sections`、`template_items` 是模板唯一的编辑来源。

- **编译**：每次保存都在同一事务里重新编译出项目生成要用的阶段、工作、检查项、资料要求、车辆环节和采购项（`services/template_items.py` 的 `compile_template`），ID 不变：
  - 工作的任务 ID = 事项 ID；
  - 资料要求 ID = 文件 ID；
  - 阶段 ID = 段落 ID。

  因此已建项目里指向模板资料要求的链接不会断。
- **写操作**：所有写接口都在模板事务锁内重新校验账号与权限，并写操作记录。权限要求：
  - 普通写操作：`system.templates.manage`；
  - Excel 导入：另需 `system.template_io.manage`。
- **新建项目**：`POST /projects` 传 `optional_item_ids`（勾选的可选事项）。必选事项全部带入，未勾选可选事项的文件不建项目资料，采购事项直接生成项目采购记录。旧客户端仍可只传 `work_item_ids`。

## 迁移

`g3a93b000001` 在线运行，不能离线跳过：

- 每个已有模板原样转换：
  - 每项工作一行，模块与车型限定等原值保留在事项的 `extra` 里；
  - 资料按原分组、按阶段合成“××资料”行；
  - 采购各一行；
  - 没有工作关联的车辆环节补成“每台车”的工作行；
  - 原分组标题行和“项目准备”提醒工作不再保留。
- 旧通用模板有工作时换成上面的精简版。已有项目的安装把原通用模板的全部内容（ID 不变）移到一个普通模板“通用模板（升级前内容）”，已建项目的资料链接仍指向原来的资料要求，不需要可以删除。
- 新装库在启动时写入精简版（`app/seed/default_template.py`）。
- 降级会删除新表；为了兼容更早的结构，会给没有模块的模板工作补上模块。

## 下线

旧的模板写接口已下线，统一由上面的段落/事项接口代替：
- 整树保存；
- JSON 导入导出；
- 旧 Excel；
- 工作项、工作分组、拖动布局；
- 车辆环节列表；
- 资料要求增删改与空白模板上传；
- 采购项增删改。

工作列表、资料要求、车辆环节、采购项的读取接口保留，读的是编译结果。
