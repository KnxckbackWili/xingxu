# 管理员与项目经理二次验证（T14）

管理员和 PM 可在账户菜单「二次验证」启用认证器。`PUBLIC_MODE=1` 时这两个角色必须启用，不能通过网页关闭。其他角色如果此前已启用，角色调整后仍需完成验证。现存未登记账号不阻止首次启动：正确密码只获得五分钟的签名登记步骤，扫描本机生成的二维码、确认一组有效验证码后才建立业务会话。取消、超时、重新登录或账号令牌版本变化使原步骤失效。

登录使用密码加六位 TOTP，或密码加一枚恢复码。协议按 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)：SHA-1、30 秒时间步、允许前后各一个时间步。服务端按账号原子记录最后消费的时间步；同一验证码不能再次登录、关闭或生成恢复码，需等待下一组。宿主须保持系统时间同步。密码验证成功不会清除第二因子失败计数；原 IP/账号桶和账号全局第二因子桶共同限流，PostgreSQL 多 worker 共用数据库计数。

每次启用或重新绑定生成十枚 128 位随机恢复码，完整内容只在当次页面显示。数据库仅存带账号域的 SHA-256 哈希与消费时间。每枚只能消费一次，并发请求最多一个成功。重新生成恢复码需要当前未使用的 TOTP，并立即作废旧码；关闭需要当前 TOTP，公开强制账号不可关闭。启停、验证、重新绑定、恢复码使用与替换均记录不含密钥/验证码/恢复码明文的审计。

## 认证器丢失

登录页输入正确账号密码后，选择「认证器丢失，使用恢复码重新绑定」，用一枚剩余恢复码进入限定用途向导。这一路径支持最后一枚恢复码；不先发业务会话，确认新认证器后原密钥和旧恢复码才被替换。也可用恢复码正常登录，再在账户设置以密码和另一枚恢复码重新绑定。向导取消后原认证器仍有效，已用于发起恢复的恢复码不会退回。

认证器及所有恢复码均丢失时，只能由已掌握部署宿主的操作员核实身份后执行本地恢复；网页没有管理员代关或重置信任接口：

```bash
# 使用当前部署自己的 Python、DATA_DIR、DATABASE_URL 和 SECRET_KEY 配置。
python backend/scripts/reset_two_factor.py --username ACCOUNT --confirm-username ACCOUNT
```

工具以独立宿主进程运行，不消费待恢复备份；存在待恢复请求时明确拒绝，须先完成受信恢复。工具只重置明确指定的账号，记录宿主恢复审计并撤销该账号全部旧会话、刷新令牌和 Agent 凭据。公开部署的管理员/PM 下次正确密码登录仍必须完成新登记。不要通过 URL 传递恢复码或把真实密钥写进工单、命令行、日志或截图。工具参数不包含密钥、密码、验证码或恢复码。

## 会话、外部工具与备份

限定用途 JWT 含独立 audience、type、purpose 和数据库单次 challenge，不能当 access/refresh 使用，也不能以旧业务会话进入强制登记。每个业务请求及刷新均按当前角色、部署模式和账号 MFA 状态检查；升任 admin/PM 后旧未验证会话立即失效。启用、重新绑定、关闭、宿主恢复提升令牌版本，并撤销已有外部凭据。MFA 账号只能从本人已验证会话创建 Agent 凭据；Agent 在认证及每个工具执行时校验当前账号政策、凭据版本、停用与过期，持续 MCP 连接也不能保留旧授权。

TOTP 密钥用 AES-256-GCM 加密，HKDF-SHA256 从持久应用 `SECRET_KEY` 派生独立认证域密钥，随机 nonce 且 AAD 绑定账号 ID。待确认密钥也密文存储；页面仅内存持有，二维码用本地 SVG 计算，不请求外部二维码服务，不写浏览器 storage/URL。敏感响应 `Cache-Control: no-store`；认证器操作的 401 直接呈现，不触发自动刷新与重复提交验证码。

沿用 T12 一致加密全系统备份：数据库中 MFA 配置、挑战及恢复码状态与 `secret.key` 一起保全，不增加独立丢失风险。若部署显式以外部 `SECRET_KEY` 覆盖文件，一致备份会把实际使用的密钥放入加密包内的 `secret.key`，不沿用可能过时的文件。恢复时若仍使用外部覆盖，须同步恢复同一外部密钥；错误覆盖将无法解密已有认证器，可用恢复码重新绑定，或走受信宿主恢复。恢复旧备份也会回到该快照中的恢复码消费状态，恢复后应重新生成恢复码。备份口令属于 T12 独立凭据，不随系统备份传播。

增量 `g3a14b000001` 接 `g3a21b000001`，SQL 冻结，不导入未来模型；增加用户 MFA 字段、单次 challenge/恢复码表及 Agent 认证版本。新字段默认未登记，既有账号与权限不改写；不支持丢弃认证数据的降级，应恢复升级前一致加密备份。
