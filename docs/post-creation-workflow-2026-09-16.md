# 创建后的启动流程改进

## 实测问题

- 总览缺少人员配置环节，下一步跳转后没有直接定位待处理任务。
- 总览提示 8 项目标待填，计划页却隐藏整个「进场准备」执行阶段，只能找到 5 项。准备提醒和执行任务被混为一谈。
- 团队页将 API 返回的成员 ID 数组当成成员对象渲染，姓名无法正确展示；安排成员需要另找项目设置。
- 准备就绪标签使用了过时文案进行判断，不能匹配接口的 `state_key`。
- 已停工、已完成、已归档项目可能仍被引导回启动配置；下达日程后项目头部状态没有刷新。

## 改动

1. 总览增加车辆、任务目标、成员、排程下达、进场条件五项可点击启动清单。根据真实项目状态给出下一步；状态推进仍使用原服务端校验。
2. 「补齐任务目标」直达待填筛选并展开相关阶段；保留进场准备执行任务。每项可直接填写目标，保存后退出编辑并刷新数量。已手动完成任务不重复要求补填。
3. 团队页解析成员姓名，可直接选择并保存成员，使用项目版本避免覆盖并发修改；失败保留选择。明确团队模板不等于添加成员。
4. 子页面提供返回启动清单入口；日程页说明预览、分配、下达和进场的区别，下达后刷新项目状态。
5. 运行中优先关注现场日程、严重问题和交付；停工与终态不展示启动清单。状态操作依据项目权限显示并防止重复提交。

## 验证

- 前端完整回归：43 个测试文件，230 项通过；TypeScript 与 Vite 生产构建通过。
- 新增覆盖：状态逐级推进、缺人员/缺目标/未分配日程、严重问题、停工及终态、进场任务筛选、成员姓名解析与保存失败重试。
- 本地演示项目浏览器验证：草稿进入准备中 → 目标筛选（8 项）→ 保存一个目标（剩 7 项）→ 加入执行成员 → 返回清单更新。
- 桌面与 390px 手机截图已保存；手机页面无横向溢出。
- 本次未更改后端业务接口、数据库结构或验收规则。清单反映配置状态，不代替实际进场确认与服务端检查。
