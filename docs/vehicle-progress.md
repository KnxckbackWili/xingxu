# T30 车辆进度表

项目“车辆”页以实际车号 × 环节展示完成日期；按车型筛选后可选中多台车，批量登记同一环节。默认环节为到场点检、单车调试、地图与站点、系统联调、上线运行。模板中心“车辆环节”可以改名称、顺序、增删环节；修改只影响新项目，已有项目保留创建时的快照。

登记填写实际完成日期，登记时间另存 UTC 时间；未来完成日期拒绝。取消勾选须填理由，保留版本和操作记录。仅有填报权限的项目成员或有相应项目能力的人可以登记，筹备、待进场、停工及结束的项目不能登记。批量操作在一个事务中核对全部车辆、环节、版本和权限；任何一项冲突时整批保留原状，刷新核对后再操作。

车辆进度表与生命周期表分开。生命周期表仍保存原有故障、处理方法和问题履历，原 Excel 导入导出保留。车辆当前环节取环节顺序中最后一个已完成项；补记较早的环节不会使当前环节倒退，取消后续环节才会改变它。原问题记录的历史阶段保持原事实，不再改写车辆当前环节。升级时原九阶段值先转存只读 `legacy_current_stage`，再将当前环节切到矩阵口径；不会丢掉原阶段事实。

项目总进度按每台车的每个环节与每个非车辆工作项等权计数。非车辆工作项满足完成条件后计一项，不再把米、次、项、台混合加权。原数量填报记录保留用于追溯，原完成数量修正入口已经移除，车辆完成量通过勾选和取消维护。项目计划与实际曲线显示每周车辆环节数；旧排程中明确关联历史环节的计划数量可按周汇总，未配置环节计划时计划曲线显示未知，不假造计划。补录的历史完成日期未知时不放进具体周。

默认模板的车辆工作已绑定默认环节：开箱/到场类工作→到场点检，单车调试五项→单车调试，系统联调类工作→系统联调（`DEFAULT_TASK_VEHICLE_STEPS`）。迁移 `g3a30b000002` 只为从未被改动过的默认模板行及三套预置模板的未改副本补绑，并写迁移审计；已有人工修改的模板与项目不动。因模板工作已关联环节，删除被关联的环节前需先调整工作关联。

## 原数量记录的保全

旧车辆任务没有可证明的默认五环节映射，逐项保留为“历史环节：原任务名”。迁移保存来源任务 ID、原目标、原累计、手动完成事实、原单位及车型范围、取整结果和差异；原任务和报工记录不修改。矩阵按台取整的计数独立于原始数量。旧混合单位加权百分比与新等权口径不同，不能把两者视为同一指标。

无法定位车号的已完成数量显示为“已完成（迁移，车号未知）”。它仍计入历史完成数，单独提示尚未逐台核验；不会自动生成车辆档案、真实车号或完成日期。目标数量原本未知则继续标为未知，保留已知完成数量，不能用已建档数量倒推整批目标。

核对并添加真实车辆后，选中车号和历史环节，使用“补录迁移车号”转移已有完成凭证。原应完成台数未知时，项目计划管理人可填写核对理由，补充矩阵应完成台数；原始目标和完成量保持不变，使用读取值校验避免覆盖并发修改。补录不增加总完成数；取消该迁移单元格会把凭证返还为车号未知。转移、取消和普通勾选共用事务锁及版本保护，历史凭证与真实单元格不能重复计算。车号未知本身只显示警示，不自行增加完成或归档硬门禁；真正未完成环节及必需安全检查仍阻止完成。

## 数据与接口

`vehicle_steps` 保存模板定义；`project_vehicle_steps` 保存项目快照；`vehicle_progress` 以真实车辆与环节唯一，撤销保留行和版本；`vehicle_progress_migrations` 独立保全历史未知身份的完成凭证。

- `GET /projects/{id}/vehicle-progress`：矩阵、真实车辆、来源警示及完成汇总。
- `PUT /projects/{id}/vehicle-progress`：`cells[{vehicle_unit_id,step_key,version}]`、`is_done`、`done_on`、`reason`、`note`、`claim_migrated`；原子批量登记/取消/补录。
- `GET/PUT /templates/{id}/vehicle-steps`：模板环节定义；写入需模板管理权限。

项目 JSON 完整导出矩阵与历史凭证到只读 execution_evidence，并保留便携矩阵字段；导入校验引用和对账后只复制环节范围，不继承完成单元格或完成凭证资格。旧数量报告的日期、操作者、数量、备注与 UUID 同样只读保留，不创建新项目的活跃报工。完整原字段、原日期、原操作者保存到 portable_unverified_snapshot，可在车辆页“查阅原始来源”查看；新项目必须重新登记完成、检查和验收。克隆同样只复制环节计划范围并留存只读来源。系统一致加密备份和旧库前向迁移仍完整恢复原 ID、日期及执行事实。保留档案包含三张项目数据表，完整备份覆盖所有新表。增量迁移要求在线逐条对账，拒绝以离线 DDL 绕过历史转换；回退需恢复升级前一致备份。
