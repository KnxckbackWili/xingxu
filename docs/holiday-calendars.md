# 节假日与调休数据

系统按年度维护中国统一放假和调休补班日期。2027 年只有在国务院年度通知发布并核对后才应录入；不能根据农历、上年日期或新闻预测表自动推算。

截至核对日，在中国政府网公开检索中未检索到《国务院办公厅关于2027年部分节假日安排的通知》。因此本轮不附造2027年春节放假或补班日期。2024年公布的长期调休原则不作为2027年度专项通知的替代。项目周期涉及2027或其它无数据年度时，计划页、项目设置、排期设置和节假日设置显示缺失警告，不把空列表显示成“全年没有节假日”。

## 维护或导入

在设置的“节假日设置”中选年度，核对官方通知后填写全年放假日、调休补班日、来源名称、HTTPS来源链接及发布日期。明确确认已核对全年再保存。所有成员可以查看年度来源，只有拥有 `system.holidays.manage` 的账号可以写入（默认管理员）；只读预设不能写入。保存记录审计并按版本拒绝覆盖他人的新修改。

可先导出某个已存在年度的JSON作为格式参考，或使用“下载年度JSON格式”。JSON字段为：`year`、`holidays`（YYYY-MM-DD字符串数组）、`workdays`（相同格式）、`source_name`、`source_url`、`published_on`（YYYY-MM-DD）、可选`note`。必须填写完整本年度，不得混入下一年、重复日期、同日放假与补班或未来发布日期。网页导入仅填表预览，不直接写库；核对后保存。文件内的版本、管理状态和确认标记不能覆盖服务器状态。

例如可以导出内置2026年实际数据；不要把缺失年度的空白格式当作已核实数据直接导入。已人工维护的年度始终显示“人工维护，请核对来源”，不会冒充内置官方已核对表。

维护结果存于数据库 `holiday_calendars`，完整数据库备份会包含这些数据。重启不会覆盖。以后软件内置表升级也不会覆盖该年度人工维护结果；如需改正，重新核对并显式保存该年度。

## 计划与补班语义

- 计划上放假日和补班日分别标记“假”“班”，无论该项目是否选择跳过节假日。
- 兼容旧日排程：开启“跳过法定节假日”时，统一放假不排，调休补班覆盖普通周末休息；手动补充休息日始终优先。不启用时沿用项目周休息规则，现场赶工不被强行改变。
- 未覆盖年度仍按已设置的周休息和手动休息日处理，并持续警告；不伪造官方日期，也不阻断人工计划。
- 修改年度数据不会自动移动已有或已发布安排。
- T40周计划接入使用项目响应中的 `holiday_dates`、`adjusted_work_dates`、`missing_holiday_years` 和 `holiday_sources`。可复用 `HolidayCalendarNotice` 展示覆盖缺失，按每周日期范围展示放假/补班标记。T41基线当前仍为旧日程页，周计划替换由T40承接。

API为 `GET /api/holiday-calendars?start_year=2024&end_year=2027`、`GET /api/holiday-calendars/{year}`、`PUT /api/holiday-calendars/{year}`。PUT除上述JSON字段外要求 `complete:true`、`expected_version`；内置或缺失年度版本为0。无数据年度返回 `available:false`，不能仅看空的日期数组。
