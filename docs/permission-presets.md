# 账号预设和权限原因

新建账号默认选择“实施工程师”，也可选“项目经理”或“只读”。无需逐项配置即可使用，项目仍须实际指定负责人或加入成员。管理员需要维护旧角色或指定管理员时，展开“高级：账号角色与逐项权限”；原账号角色不自动变更。

只读预设使用独立 `readonly` 角色，继续使用原有角色字段，不需转换现存账号或数据。它只允许读取已获可见权限的项目和下载共享资料；消息可标记已读，本人仍可改密码。项目写入、系统维护、提交问题和资料均拒绝。系统单项允许及项目额外授权不能越过该预设；如需写入，先由管理员在账号高级设置中改变角色。新动作默认不属于只读允许列表。

成员授权移到项目设置的“成员授权”。原项目人员页保留参与人员安排和跳转设置的链接。每名成员可通过“查看无权限原因”读取服务端当前已保存的判断：账号停用、系统禁止、只读预设、不是项目成员、项目角色没有相应能力。本人可查自己，负责人和有成员管理能力者可核对项目内成员；不会取得其他项目或账号的私密资料。

被拒操作显示相应原因。不可见项目继续统一返回404，提示项目不存在或未获查看权限，不据此暴露项目存在性；成员管理者可在原因面板获得具体项目关系判断。权限原因查询只读，不改变任何授权。

旧角色、现有明确禁止、非项目成员隔离、CAS版本及审计保持。新账号审计记录实际采用的角色；每项权限设置收在高级中，并继续保留未保存、冲突和导航离开保护。
