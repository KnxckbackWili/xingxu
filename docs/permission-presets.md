# 账号预设和权限原因

新建账号默认选择“实施工程师”，也可选“项目经理”或“只读”。无需逐项配置即可使用：所有启用账号都能看到全部项目并登记现场事实，项目负责人和技术负责人在项目设置里指定。管理员需要维护角色或指定管理员时，展开“高级：账号角色与逐项权限”。

只读预设使用独立 `readonly` 角色，继续使用原有角色字段，不需转换现存账号或数据。它只允许读取已获可见权限的项目和下载共享资料；消息可标记已读，本人仍可改密码。项目写入、系统维护、提交问题和资料均拒绝。系统单项允许及项目额外授权不能越过该预设；如需写入，先由管理员在账号高级设置中改变角色。新动作默认不属于只读允许列表。

每个账号可通过“为什么不能操作”读取服务端当前判断：账号停用、系统禁止、只读预设、账号角色或项目职责没有此能力。

被拒操作显示相应原因。不存在或已删除的项目返回404。权限原因查询只读，不改变任何授权。

明确禁止、CAS版本及审计保持。新账号审计记录实际采用的角色；每项权限设置收在高级中，并保留未保存、冲突和导航离开保护。

## 系统权限一键开通

系统权限页（设置 → 高级 → 成员权限）选中成员后，先显示“一键开通”开关，每个开关对应一类工作，打开后点“保存权限”：

| 开关 | 包含的权限 |
|---|---|
| 新建和导入项目 | `projects.create`、`system.import.create` |
| 查看全部项目和归档 | `projects.view_all`、`system.archives.read` |
| 维护模板和车型 | `system.templates.view`、`system.templates.manage`、`system.template_io.manage`、`system.vehicle_types.view`、`system.vehicle_types.manage` |
| 管理人员账号 | `system.users.read`、`system.users.manage`、`system.availability.manage` |
| 备份、通知和节假日 | `system.backups.*`、`system.notifications.configure`、`system.holidays.manage` |
| 处理系统反馈 | `system.feedback.manage` |

开关只写入与角色默认不同的单独设置（角色已有的权限打开时不另存，关闭时写“禁止”），“恢复为角色默认”清空全部单独设置。“权限管理”入口仍仅限真实管理员身份，不在开关里。逐项设置收在“高级：逐项权限设置”。
