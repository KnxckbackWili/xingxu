# 发车前资料确认

进入现场实施只核验项目当前适用的第5阶段必需资料。已提交资料必须有真实、完整的最新附件；不适用必须有理由。车辆范围资料尚未生成时不会被当作已齐备，需核对车辆与输出时机。已授权清理的旧周期仅凭精确保全凭据保留历史提交资格；最新一期及无凭据原件缺失仍拦截。采购项保留独立数量、规格、日期、完成记录和审计，不作为进场门禁。

资料齐备后可人工推进项目状态。存在缺项时，有项目计划管理权限的人员必须核对当前快照、填写理由并明确批准风险进场。批准不会把缺项改成已提交，不会自动改变项目状态。新增必需资料、已齐备资料撤回或原件丢失、要求变化、截止提前或原缺项变为逾期后，需重新确认。

新接口：

- `POST /api/projects/{id}/documents/dispatch-review`：只读核对，返回当前快照校验值。保密查看仅记录相应访问审计。
- `POST /api/projects/{id}/documents/dispatch-review/confirm`：`conclusion` 为 `ready`、`risky` 或 `not_ready`，附 `notes` 和必填 `review_token`。锁定项目并重算全部条件；条件变化返回409。
- `GET /api/projects/{id}/documents/dispatch-review/history`：保留确认历史，旧准备评审标为原记录，不授予当前进场资格。

旧 `preparations/confirm-ready`、`preparations/review`、`preparations/review/confirm`、`preparations/reviews` 返回410。原评审行及快照不修改，完整数据仍进入私有加密项目备份。保密条件仅向有查看权限的人显示名称；确认说明不会复制到普通项目详情，历史说明按当前保密范围过滤。

现场实际操作仅允许处于“现场实施”“验收中”的项目：车辆矩阵、逐车或旧NULL检查项、直接完成、重新打开、数量记录和撤回均在服务端检查；离线同步复用同一检查。准备阶段仍可提交资料和上报问题。重复历史UUID只返回已有幂等结果，不生成新事实。

前端确认页面在项目、账号或权限变化时清空旧状态；旧请求的迟到结果不能关闭另一个项目的确认弹窗或锁住新项目。
