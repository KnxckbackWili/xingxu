| 环节 | 原问题及业务影响 | 修复原则 |
|---|---|---|
| 重排 | 目标4，锁定已有2后重排，总量变6 | 保留受保护记录，仅排剩余数量 |
| 重排 | 第一天已填报，后续未填报日程被删除且未补回 | 已填报记录与数量完整保留，再补排未覆盖量 |
| 任务顺序 | 已确认前序未推进排程时间；逾期任务被安排同日 | 保持阶段与模块内既定顺序 |
| 模块并行 | 不同模块排序号相同，被当作同模块串行 | 按模块身份分组 |
| 完成工作 | 手动完成、已有无日程关联填报的工作仍被全量排程 | 排程考虑已完成工作 |
| 截止日 | 正好在截止日完成仍误报超期 | 使用实际最后工作日判断 |
| 现场填报 | 无关项目PM可以根据任务ID写入报工、修正和完成操作 | 统一项目可见性及计划管理能力校验 |
| 离线填报 | 两次独立离线新增复用UUID，第二笔被去重吞掉 | 每次成功入队后生成新UUID，重试仍保留原UUID |
| 质量检查 | 当日数量填满后检查按钮禁用 | 数量完成不妨碍补检和复核 |
| 不适用 | 现场人员的正常“不适用”提交总是403 | 保留成员权限、理由必填、安全项禁止跳过 |
| 日程下达/取消 | 取消日程仍显示并接受填报；未下达也可现场填报 | 过滤取消记录、校验下达；保留授权PM补录和成功请求重试 |
| 项目完结 | 加权或小数取整显示100%，但任务实际未完成 | 完成门禁使用逐任务原始数量及检查状态，而非展示百分比 |
| 验收 | 后端要求验收记录，前端无录入入口 | 增加验收签字记录列表和录入入口 |
| 问题重开 | 后端已有重开接口，现场和管理页面缺少可达入口 | 展示已解决记录并提供受权限控制的重开入口 |
| 归档 | 归档项目的问题及检查结果仍可修改 | 统一归档只读限制 |
| 车型备注 | 仅修改备注也重新计算并覆盖人工目标量 | 仅实际数量/车型改变才触发既有重算 |
