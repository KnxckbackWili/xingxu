# 项目准备流程与进场确认

## 用户问题

创建项目的「项目条件」与实施范围重复，用户无法预知影响；未默认选中的实施模块在最终确认时被隐藏。进场评审等待接口返回后才打开，未完成项只显示计数；提交有风险进场后，状态摘要重新显示未就绪，让确认看起来没有生效。

## 行为

- 移除集中条件勾选区。车辆来源、国内/海外、服务器提供方放入相应资料区域。
- 创建时全部实施模块可选；取消后仍能重新选回。
- 模块通过显式 `preparation_conditions` 关联接口/充电准备项；模板复制、改名、编辑保留关联。
- 预置方案新增可选 WMS/MES 对接实施模块。接口文档随对接工作带入。
- 创建前展示完整准备清单及来源，包括进场实施任务同步的事项；创建接口自行推导条件。旧接口的 `need_wms/need_charging` 显式参数继续兼容。
- 后续补充实施工作时幂等补齐准备事项，保留已有状态。
- 确认窗口立即打开，可见加载/失败/重试反馈；逐项列出未完成和阻塞事项。
- 正常确认需要清单落实；强制确认必须填写非空理由，保留原清单、确认人、理由和快照。
- `entry_confirmed` 区分确认结论与事项完成率；强制确认用 `state_key=forced_ready` 展示。开工安排立即同步。
- 清单发生变化时拒绝过期确认（409）；新增未完成项或风险加重使确认失效。未完成项逐步补齐不会撤销已接受的确认。

## 验证

专项测试覆盖范围选择/取消/排除、模板复制改名、后续添加幂等、强制确认理由校验、权限、确认快照、过期清单、不适用项及空清单。

浏览器使用独立本地演示数据库：从创建到确认走通；创建前预览 28 项与创建后的 28 项逐条相同。勾选及取消 WMS/MES、自动充电正确联动；强制确认后开工步骤即时显示完成，理由与 28 项快照在历史中可查；390px 手机宽度无页面水平溢出。

使用生产数据库副本连续执行两次初始化/迁移，对既有项目、任务、阶段、模块、检查项、准备事项、评审和用户做内容哈希比对，保持一致。升级只增加模板关联和可选工作，不改变存量项目执行范围。

本轮回归：后端全量 683 项通过、前端全量 248 项通过；最后两处确认校验调整后，17 项准备/评审测试再次通过。TypeScript、Vite 与 PWA 构建通过。已随日程与工作区调整于 2026-09-16 部署到 7001，运行提交为 `d51d011`。
