# 系统页面与入口清单

2.3 界面沿用常用工作入口，并增加全系统成员权限，路径、权限和业务规则沿用原契约。以下列完整功能；当前账号实际能看见哪些入口，由全系统权限、路由守卫与项目能力共同决定。整改证据见[整体界面重设计清单](整体界面重设计清单-20261007.md)，查找旧名称见[名称与入口指引](功能位置与名称指引-20261007.md)。历史版本页面说明不再作为当前导航依据。

## 先找入口

| 位置 | 当前入口 | 怎么使用 |
|---|---|---|
| 管理端顶部 | 工作台、项目、人员、消息 | 常用四项直接进入；手机以第二排保留，不必先打开菜单 |
| 顶部“全部功能”（手机显示“菜单”） | 常用、个人工作、资料与统计、项目管理、管理设置、使用反馈 | 每项有一句用途；可搜索当前名称、旧名称或用途 |
| 项目目录 | 概况、准备、任务、日程、人员、现场、资料 | 常用七项；现场、资料可点箭头展开，不先跳页面 |
| 项目“现场” | 问题、车辆、物品、联系人 | 新的“现场”入口默认问题；不改旧 `/site` 的车辆落点 |
| 项目“资料” | 全部文件、提交资料、验收、报告 | 新的“资料”入口默认全部文件；不改旧 `/delivery` 的提交资料落点 |
| 项目“查找功能” | 全部可访问项目功能 | 可按名称、用途或旧名称搜索；手机在“项目菜单”内查找 |
| 项目“更多” | 开工向导、项目设置、操作记录、导出 | 低频工具集中保留；手机用同一个“项目菜单”查找 |
| 现场端底部 | 今天、日程、问题、项目、我的 | 消息在顶栏通知铃；使用反馈与修改密码在账户菜单 |

管理端 Ctrl/⌘K 打开全站功能查找；项目中优先打开项目菜单。Escape 关闭后返回触发按钮；未保存保护阻止离开时，不先切页或清掉输入。

## 登录与公共页面

| 路径 | 页面与首要用途 | 首屏与主要动作 |
|---|---|---|
| `/login` | 登录 | 账号、密码、登录；安全保留被拦截的原目标地址，按角色选择默认落地 |
| 无权限 URL | 403 | 说明无访问权限并给返回入口；菜单隐藏不替代路由或后端判权 |
| 不存在 URL | 404 | 返回首页；项目不可见或不存在时使用不泄漏原因的友好提示 |

管理工作台角色默认进入 `/pm/dashboard`，实施/实习角色默认进入 `/worker/today`。历史角色映射继续兼容，正常创建账号仍按当前三级角色政策。

## 全站页面

以下路径可以从“全部功能”按权限查找。页面主动作也按实际能力显示，不是每个账号都拥有表内写操作。

| 当前名称 / 路径 | 用途 | 当前首屏与主要动作 |
|---|---|---|
| 工作台 `/pm/dashboard` | 先处理待办，再看项目与风险 | “现在要处理”与项目列表优先；新建项目、打开项目；统计和管理分析退到后面 |
| 项目 `/pm/projects` | 打开、新建、导入可见项目 | 搜索、状态筛选与卡片/表格；卡片和表格可直接打开任务、日程；新建向导“项目资料→工作内容→确认创建”，默认草稿；JSON 导入先预检 |
| 人员 `/pm/people` | 安排人员与查看负荷 | 页面标题“人员安排”；人员日程、人员看板、项目成员、人员名册；成员与不可用时段按原权限调整 |
| 消息 `/pm/messages` | 查看通知并回到对应工作 | 未读/类型筛选、通知列表、查看未读与标记已读；手机完整详情在抽屉内，相关工作可直达 |
| 我的日程 `/pm/my-schedule` | 查本人安排并自助调整允许修改的工作 | 日期视图、当天明细、添加个人日程；已下达/锁定等保护继续生效 |
| 团队日程 `/pm/team-schedule` | 按日期查看可见团队工作 | 人员筛选、月历、当天明细；本页汇总只读，工作详情操作仍按项目能力 |
| 物品总览 `/pm/inventory` | 跨项目找物品、位置与库存 | 筛选与物品列表/手机卡片优先；打开对应项目；归属与异常汇总折叠 |
| 统计 `/pm/stats` | 比较可见项目进展、人员产出 | 项目、人员等统计视图；不同单位分别显示，时间选择放在对应趋势区；嵌入工作台不重复页标题 |
| 项目移交 `/pm/governance` | 申请或处理项目负责人移交 | 新申请仅办理移交；旧删除申请保留历史，不再审批删除 |
| 项目回收站 `/pm/project-recycle-bin` | 找回误删项目 | 删除先备份、不审核；有删除权限的人可按原项目ID还原或下载单项目备份；不恢复全系统 |
| 成员权限 `/pm/permissions` | 按成员设置全系统操作 | 真实启用管理员；权限目录中的按模块分组，继承/允许/禁止、搜索、批量、固定保存、冲突与未保存保护 |
| 账号 `/pm/users` | 维护账号和角色 | 搜索/角色/状态筛选、新建账号；启停不等于硬删除，旧角色编辑保留原值 |
| 项目模板 `/pm/templates` | 维护新项目的工作内容 | 模板选择与任务树优先；使用模板新建项目；编辑/保存，导入导出与复制删除收在其他操作 |
| 车型库 `/pm/vehicle-types` | 维护建项目时可选车型 | 搜索/状态、车型列表、添加车型；筛选后排序仍基于完整源列表位置 |
| 通知设置 `/pm/notification-channels` | 配置站外通知 | 当前启用状态优先；配置、复杂参数、Secret 与测试功能展开后使用；本地取消恢复已保存配置 |
| 备份与恢复 `/pm/backups` | 保存或恢复完整系统备份 | 立即备份与已有包列表优先；恢复区域单独展开，仍需兼容检查、明确确认与重启流程 |
| 外部工具接入 `/pm/ai-tokens` | 授权外部程序访问限定项目功能 | 令牌列表与创建令牌优先；权限范围、连接说明和技术参数按需查看；按账号项目范围查询与预览 |
| 使用反馈 `/pm/feedback` | 反馈软件使用问题或处理反馈 | 管理人员先看处理列表，填写反馈单独入口；普通用户聚焦文字与复现步骤，提交后可确认成功 |

`/pm/ai`、`/pm/ai-assistant` 是兼容入口，当前跳到 `/pm/projects`；不再列作独立通用聊天页面。`/pm/progress` 兼容跳到 `/pm/dashboard`。

## 项目内页面

路径前缀统一为 `/pm/projects/:projectId/`；仅项目可见账号可读，写按钮由项目能力与阶段决定。项目头部只保留名称、当前状态、短资料及“项目信息”抽屉；同项目切页保留框架并后台刷新。

| 所在区域 | 名称 / 路径段 | 用途与首屏 |
|---|---|---|
| 常用 | 概况 `overview`（无段时同页） | 当前状态、下一步、待处理工作和工作进度；阶段推进须授权与有效证据，长说明按需查看 |
| 常用 | 准备 `preparation` | 准备状态/责任方/负责人/日期与采购；默认聚焦待处理；选择已通过/不适用会自动取消待处理限制，评审“去处理”可直接定位；补充要求与评审展开填写 |
| 常用 | 任务 `plan` | 项目做什么与目标数量；按阶段列任务，目标可就地填写；打开任务看检查、参考资料、提交资料及记录，检查/完成保护不变 |
| 常用 | 日程 `schedule` | 哪天、谁做、计划多少；甘特按任务/人员分组、展开每日分工、按实际日查看并调整单条安排；清单与手机日历完整卡片，全部任务重排直接在页头（先预览再确认），排期设置及逾期/受阻调整在更多；人工工期、倍率、已有填报与锁定保护保留 |
| 常用 | 人员 `team` | 项目成员、岗位和操作授权；先添加实际成员，再去安排日程；成员身份与操作授权分别查看 |
| 现场 | 问题 `issues` | 待解决/待关闭优先；上报、指派、开始处理、填写解决结果、确认关闭；车辆故障走车辆记录，不重复建档 |
| 现场 | 车辆 `vehicles` | 实车身份、位置/状态与故障维修履历；登记车辆、更新位置与记录问题按既有权限 |
| 现场 | 物品 `inventory` | 物品、位置、保管人和库存流水；采购申请单独分区；出入库/整批转移等保持原数量语义，只读申请不能伪保存 |
| 现场 | 联系人 `handover` | 页面标题“联系人与入场”；客户联系人、客户单位/小组、电话、签字范围、入场条件与交接记录 |
| 资料 | 全部文件 `files` | 项目附件中心；按分类查找、上传、下载，文件所属任务与权限保留 |
| 资料 | 提交资料 `delivery` | 汇总任务所需交付资料；按实际待办选择首次范围，提交→待审核→通过/退回；链接直达对应任务的资料页签 |
| 资料 | 验收 `archive` | 当前范围验收记录、归档清单、附件关联与项目复盘；归档/未知状态等只读保护保留 |
| 资料 | 报告 `reports` | 周报/月报、期次选择、按单位的工作与问题摘要、打印；不与操作记录混在同一首屏 |
| 更多 | 开工向导 `start` | 工作内容、人员、日程、进场四步；复用相应页面内容，嵌入时不重复标题和保存动作 |
| 更多 | 操作记录 `activity` / `history` | 操作人、当地时间、变更内容；查询已加载的全部记录，不只最初可见片段 |
| 更多 | 导出 `export` | 推荐完整项目 ZIP；其他导出、JSON 预检导入、生命周期表、甘特 PDF、克隆按需展开 |

### 兼容路径与复用规则

- `tasks` 继续显示任务；`site` 继续显示车辆；`delivery` 继续显示提交资料；`activity` 与 `history` 继续显示操作记录。展示分组不批量改旧地址，也不改变后端字段含义。
- 深链接 `plan?task=<id>&tab=deliverables` 打开指定任务与提交资料页签；`issues?report=1` 保留上报入口；日程 `?view=gantt` 保留甘特视图。
- 新项目默认草稿；项目阶段、任务分组、准备评审结果与进度百分比分开。正常推进和门禁见[项目创建与阶段说明](project-lifecycle-remediation-2026-10-06.md)，界面改造不重新定义状态转换。
- JSON/克隆复用新项目时，继承合法的计划倍率与人工工期预算，但不继承执行确认、报工、验收权威或成员操作授权。模板新建默认自动估算。完整项目 ZIP 额外保存只读验收与复盘记录；它们不是导入后的新项目验收依据。

## 现场端页面

底部五个常用入口始终围绕现场工作；不在每页混入管理员配置或完整排程工具。

| 路径 | 页面 / 用途 | 首要动作与阅读内容 |
|---|---|---|
| `/worker/today` | 今天 | 先看当前任务，点“打开填报”填数量；检查、资料与问题分别展开；逾期与离线状态有独立位置 |
| `/worker/schedule` | 日程（页面标题“我的日程”） | 查后续安排与当天工作；填数量仍到“今天”，项目下达和锁定状态如实显示 |
| `/worker/issues` | 问题 | 上报与跟进可见项目问题；填写解决结果、关闭等按能力，未授权没有状态写入口 |
| `/worker/projects` | 项目（页面标题“我的项目”） | 搜索参与项目；进度条显示项目实际数据；去填报或进入项目资料 |
| `/worker/projects/:projectId` | 项目详情 | 查看该项目进展、任务与资料；项目管理读页面可按原权限打开 |
| `/worker/my` | 我的（页面标题“我的记录”） | 填报记录与个人统计两个页签；允许撤回的记录按原契约处理 |
| `/worker/messages` | 消息 | 顶栏通知铃及独立页；未读、完整详情与相关工作跳转，与管理端复用组件 |
| `/worker/feedback` | 使用反馈 | 账户菜单进入；描述问题与复现步骤，不出现管理字段 |

旧 `/worker/records` 跳到 `/worker/my`，旧 `/worker/stats` 跳到 `/worker/my?tab=stats`。离线记录按账号隔离，退出前存在未同步记录时保留明确提示。

## 共用界面能力

| 组件 | 入口 | 行为 |
|---|---|---|
| 通知铃 | 管理/现场顶栏 | 未读数字、最近通知、查看全部与已读处理 |
| 账户菜单 | 顶栏姓名 | 修改密码、退出；现场端还有使用反馈；键盘开启、关闭和回焦 |
| 操作提示 | 相关功能旁小按钮 | 首次可见触发点提供解释，可关闭；也可手动再看，不授予额外权限 |
| 工作详情 | 人员、日程等工作入口 | 查看对应项目/任务/安排；调整与填报按项目能力及历史保护 |
| 离线队列 | 现场今天 | 本机按账号保存待同步记录，恢复网络后提交；失败有反馈，不显示伪成功 |

新增页面或入口时，应同步 `constants/nav.ts`、`constants/projectNav.tsx`、路由守卫与本清单；本清单记录当前位置，不替代权限或业务事实来源。
