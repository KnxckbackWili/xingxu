# 模板与项目的使用体验调整

## 问题

原流程让使用者先创建项目，再猜哪些任务应该带入、哪些数量要填写。模板只表现为任务复制库，项目没有明确的来源；准备项和采购库可能使用默认模板，补充任务可能覆盖现场调整。预置场景还存在先初始化模板元数据、后初始化默认内容导致的空模板。

## 新流程

1. 选择实施方案，直接按阶段、模块和工作项裁剪范围。
2. 填写项目、车辆和现场条件。
3. 确认具体工作量：车辆工作自动计算，培训人数等现场数量单独填写。未填写的项目保留为待确认。
4. 创建后进入项目计划，显示方案来源。补充工作默认使用同一方案，只显示尚未带入的内容。
5. 模板作为可重复使用的标准，项目保留独立阶段、工作、检查和参考资料。后续模板修改或删除不改变已有项目。
6. 复制项目继承项目实际范围及现场修改，重置执行状态，而非按名称重新套模板。

模板编辑保留稳定标识、参考资料、阶段规则和模块默认选择。编辑器明确删除的阶段不再保存后恢复。准备提醒和采购候选来自所选方案。

## 数据兼容

启动迁移新增 modules.source_module_id，已有项目引用的模板阶段迁为项目独立阶段（重复执行安全）。仅修复没有内容且没有编辑记录的已知预置模板。数据库和上传文件保持原位，部署前通过 SQLite backup 保存一致性备份。
