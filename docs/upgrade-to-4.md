# 从 3.x 升级到 4.0

4.0 是从零重写的版本：只保留记录和查看，数据表从 50 张变成 16 张。**它不读 3.x 的项目数据。**

## 升级时自动发生的事

管理员在 3.8.0 的“设置 → 软件更新”里更新到 4.0.0（或手动换镜像）后，新版本第一次启动时：

1. 如果设置了备份口令，先做一次加密备份。
2. 发现数据库不是 4.0 的基线，把它**原样挪开**，不删除：
   - SQLite：数据库文件移到 `DATA_DIR/old-<时间>/`；
   - PostgreSQL：全部表移到 `old_<时间>` 架构。
3. 旧的上传文件移到 `DATA_DIR/old-<时间>/uploads/`。
4. 建立 16 张新表。
5. **把账号带过来**：用户名、姓名、密码、是否管理员、是否停用。原来的密码照常登录。只带账号，不带项目数据。
6. 写入一个默认模板和车型库。

升级后系统里没有项目。需要的话，用车辆页的“导入生命周期表”把车辆和车辆记录导进新项目。

## 注意

- **升级是单向的。** 想回到 3.8.0，只能用升级前的备份恢复。请在升级前确认备份口令已设置、备份已下载到别处。
- 旧版本在浏览器里留有离线缓存。4.0 带的 `sw.js` 会在打开页面时自动清除它；如果某台设备仍显示旧界面，刷新一次即可。
- 已登录的设备需要重新登录一次。
- 如果旧库里没有任何启用中的管理员，启动时需要 `INITIAL_ADMIN_PASSWORD` 来创建 `admin` 账号。
- 两步验证已取消，升级后登录只需要用户名和密码。
- 不再使用的环境变量（周报时间、通知渠道等）留在配置里不影响启动。

## 核对

升级演练在两种数据库上都做过：旧库和旧文件原样保留在旁边，账号能用原密码登录，新系统是空的。自动测试见 `backend/tests/test_upgrade_cleanup.py`。
